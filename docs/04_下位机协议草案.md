# 04 下位机通讯协议（草案 v0.1）

状态：**后端方草案**，需与下位机（MCU）同事逐条确认后定稿。原始需求只规定"地址 + 指令"，其余为本方提议。所有 TBD 见 §9。

最近更新：2026-10-24，已按 P2b 实现同步。

## 1. 链路

- 以太网 TCP，下位机作 server（默认 `192.168.1.30:5000`），算力盒作 client 主动连接并在断线后指数退避重连（0.5 s → 5 s）。
- 退避规则：连接失败从 0.5 s 起翻倍，上限 5 s；连接在收到首个 STATUS 之前（或存活不足 2×心跳超时 = 2 s）即断开，视同连接失败继续指数退避；稳定连接断开后从 0.5 s 重新开始。
- `TCP_NODELAY` 开启；内核 keepalive（idle 2 s / interval 1 s / count 3）。
- 一条连接承载全部指令；算力盒是**唯一主机**，下位机只响应与上报，不主动发控制。
- 备选：CAN 2.0B 500 kbps（同样的指令集，帧拆分规则另定）；UART 仅应急。

## 2. 帧格式（小端）

| 偏移 | 长度 | 字段 | 说明 |
|---|---|---|---|
| 0 | 2 | SOF | 固定 `0xAA 0x55` |
| 2 | 1 | VER | 协议版本，当前 `0x01` |
| 3 | 2 | SEQ | 序列号，主机每帧递增（回绕）；下位机在应答中原样返回 |
| 5 | 1 | ADDR | 设备地址：`0x01` 主控（默认）；`0xFF` 广播（无应答）。预留多板扩展 |
| 6 | 1 | CMD | 指令码（§3）；应答 = 请求 CMD | 0x80；上报类 `0xC0~0xCF` |
| 7 | 2 | LEN | PAYLOAD 字节数（0~1024） |
| 9 | LEN | PAYLOAD | 指令负载 |
| 9+LEN | 2 | CRC16 | CRC16-MODBUS（多项式 0x8005 反射 0xA001，初值 0xFFFF），覆盖 VER~PAYLOAD（偏移 2 到 9+LEN−1） |

- 粘包/半包：接收方按 SOF 同步、按 LEN 取帧、CRC 不对则丢弃并从下一个 SOF 重新同步。
- 接收方头部合理性校验（后端已实现，建议下位机同样实现）：SOF 后的 `VER≠0x01`、`ADDR∉{0x01, 0xFF}`、`CMD=0x00` 或 `LEN>1024` 视为失步，立刻丢弃该 SOF 并从下一个 SOF 重同步，不等 LEN 字节到齐（否则被破坏的 LEN 会让接收方吞掉后续有效帧）。
- 建议增加 LEN 保护（头部 CRC8，或按 CMD 限定 LEN 的合法值）——TBD，见 §9。
- 多字节整数小端。

## 3. 指令集

### 3.1 主机 → 下位机

| CMD | 名称 | PAYLOAD | 需 ACK | 说明 |
|---|---|---|---|---|
| 0x01 | HEARTBEAT | `host_ms u32`（主机单调毫秒） | 是（应答为 STATUS 0x81） | 每 200 ms 一次；主机**不等 ACK、不重发**；允许 `result≠0` 的 1 字节 NACK（如 fault 态回 5），任何 CRC 正确的 0x81 帧都刷新主机的心跳看门狗 |
| 0x02 | SYNC | `flags u8`（bit0=清零编码器计数） | 是 | RUN 前发送，建立行号/编码器零点 |
| 0x10 | RUN | 无 | 是 | 开始分选：给料+输送+喷阀使能（具体动作 TBD） |
| 0x11 | PAUSE | 无 | 是 | 暂停：停给料、不喷（输送是否停 TBD） |
| 0x12 | STOP | 无 | 是 | 全停 |
| 0x20 | SET_PARAM | `n u8`, 然后 n × {`id u16`, `value i32`} | 是 | 批量写参数（§4） |
| 0x21 | GET_PARAM | `n u8`, n × `id u16` | 是（应答带值） | 读参数 |
| 0x30 | VALVE_TEST_SINGLE | `hole u16` | 是 | 单阀检测：喷头 `hole` 吹一次（按当前开阀参数） |
| 0x31 | VALVE_TEST_CYCLE | `from u16`, `to u16`, `interval_ms u16` | 是 | 循环检测，从 from 到 to 依次吹 |
| 0x32 | VALVE_TEST_STOP | 无 | 是 | 停止循环检测 |
| 0x33 | VALVE_RESET | 无 | 是 | 复位喷阀驱动 |
| 0x34 | CLEAN_NOW | 无 | 是 | 立即执行一次清灰 |
| 0x40 | EJECT | `n u8`, 然后 n × {`line u32`, `nozzle_first u16`, `nozzle_last u16`, `flags u8`} | **否** | 喷阀指令批（§5） |
| 0x7F | RESET_LINK | 无 | 是 | 下位机清空待执行队列（用于重连后） |

### 3.2 下位机 → 主机

| CMD | 名称 | PAYLOAD | 说明 |
|---|---|---|---|
| CMD\|0x80 | ACK | `result u8`, 其后可选数据（GET_PARAM 应答为 n × {id u16, value i32}） | result：0 成功；1 CRC 错；2 未知指令；3 参数越界；4 当前状态不允许；5 设备故障；6 队列满 |
| 0x81 | STATUS | `result u8` + StatusPayload（19 B，§6）= 20 B；仅 1 B（只有 result）= NACK | 对 HEARTBEAT 的应答（SEQ 原样返回）；主动上报（若有）**推荐**同样带 result 字节；主机兼容接受恰为 19 B 的裸 StatusPayload（视为主动上报，result=0），见 §6 / §9 #13 |
| 0xC0 | EVENT | `code u16`, `level u8`（0 信息/1 警告/2 故障）, `detail u32` | 故障/事件上报（§7） |
| 0xC1 | COUNTERS | `eject_rx u32`, `eject_done u32`, `eject_dropped u32`, `period_ms u16` | 每 1 s 上报，用于对账 |

### 3.3 时序要求
- ACK 应在 50 ms 内返回；主机 200 ms 未收到则重发同一 SEQ，最多 3 次，仍失败则置链路故障。
- 下位机对重复 SEQ 的指令应幂等（仅重发 ACK，不重复执行）。
- 心跳为"发出即忘 + 看门狗"：主机不等 HEARTBEAT 的 ACK、不重发、不计入 ACK 超时；主机 1 s 未收到任何 CRC 正确的 STATUS（含 NACK）→ 链路故障并断开重连；下位机 1 s 未收到 HEARTBEAT → 停喷阀（安全态），给料/输送是否停 TBD。

## 5. 喷阀指令 EJECT（核心）

- 每个 512 行块处理完后，主机把本块要吹的颗粒合并为一帧 EJECT（n ≤ 100，超出拆多帧）。
- 字段：
  - `line u32`：颗粒**尾沿**经过相机线的全局行号（自 SYNC 起）；
  - `nozzle_first/last u16`：喷头区间（全局编号，从 1 起；`0~768` 对应界面孔位）；
  - `flags u8`：bit0 预留"强吹"（延长开阀），其余保留。
- 下位机换算：`fire_at_pulse = line × lines_per_pulse + delay`（若 delay 以脉冲计）；在编码器计数到达时对区间内喷头开阀 `valve_open_time`，之后按 `valve_hold`/`valve_reblow` 执行维持与重吹（语义 TBD）。
- 不等 ACK；到达时已过期（`fire_at_pulse < 当前计数`）的条目计入 `eject_dropped`。
- 队列容量建议 ≥ 2000 条；队列满时 ACK result=6（仅在主机显式要求 ACK 时）并计数丢弃。

## 6. STATUS 负载

STATUS(0x81) 帧的 PAYLOAD = `result u8` + 下表（19 B，小端，`<BIHIHHI`），共 20 B；`result≠0` 时可只回 1 B result（NACK，不带下表）。主动上报（若有）推荐同样带 result 字节（=0）；主机当前**两种都接受**：≥ 20 B 按"result + 下表"解析，恰为 19 B 的裸下表按主动上报解析（result 视为 0），1 B 为 NACK，其他长度丢弃并告警。是否统一只用 20 B 列入 §9 #13。

| 字段 | 类型 | 说明 |
|---|---|---|
| state | u8 | 0 stopped / 1 running / 2 paused / 3 fault / 4 valve_test / 5 cleaning |
| encoder_count | u32 | 当前编码器计数（自 SYNC 起） |
| belt_speed | u16 | 当前带速（脉冲/s 或 mm/s，TBD） |
| faults | u32 | 故障位图：**bit n ↔ §7 事件码 n**（bit1 气压低、bit2 喷阀过流 … bit8 队列溢出、bit16 急停；后端据此映射为 §7 文字），待 MCU 确认（§9） |
| queue_len | u16 | 待执行喷阀条目数 |
| pressure | u16 | 气压（0.1 kPa，若有传感器；无则 0xFFFF） |
| host_ms_echo | u32 | 回显 HEARTBEAT 的 host_ms，用于估算往返延迟 |

## 7. 事件 / 故障码（建议）

| code | 含义 |
|---|---|
| 0x0001 | 气压低 |
| 0x0002 | 喷阀驱动过流/短路（detail = 喷头号） |
| 0x0003 | 编码器无信号（运行中） |
| 0x0004 | 编码器反转 |
| 0x0005 | 给料机故障 |
| 0x0006 | 输送带故障 |
| 0x0007 | 心跳超时已自动停阀 |
| 0x0008 | 喷阀队列溢出 |
| 0x0010 | 急停触发 |

## 8. 典型时序

```
连接建立
  主机 → SET_PARAM（全部参数）→ ACK
  主机 → RESET_LINK → ACK
  每 200 ms：HEARTBEAT → STATUS（主机不等 ACK、不重发）

点击运行（后端 stopped → running；已实现：RuntimeService.start）
  主机 → SYNC(清零) → ACK            （同时把全部相机行号归零；SYNC + 行号归零只在这一处一起完成）
  主机 → RUN → ACK                    （先起流水线再发 RUN；流水线起不来则不发 RUN，返回 409）
  主机 → EJECT, EJECT, ...（不等 ACK）
  下位机每 1 s → COUNTERS

点击暂停 / 恢复 / 停止
  主机 → PAUSE → ACK                  （后端流水线继续采集、分类、统计，不再发 EJECT）
  主机 → RUN → ACK                    （恢复：不发 SYNC、不重置行号，假定 PAUSE 期间皮带停、编码器计数冻结，见 §9 #14）
  主机 → STOP → ACK                   （fault 态下 HMI 点停止同样转发 STOP；关机 / 重启前也先 STOP）

任何故障（相机掉线 / 超时、下位机 EVENT level=2 或 STATUS 故障位、流水线 / 分类器连续失败、模型加载失败）
  主机 → STOP → ACK                   （尽力：下位机在线才发；下位机断线本身触发的故障且没有流水线在跑时不发）
  后端停流水线、取消采样 / 喷阀检测任务；全部故障清除后状态回 stopped，需人工再次点击运行（重新 SYNC）

链路断开
  下位机 1 s 内停阀；主机重连后重发 SET_PARAM 全量 + RESET_LINK（不发 SYNC；SYNC 只在点击运行时发），状态机置 stopped，需人工再次运行
```

3. 延时的基准：编码器脉冲数（推荐）还是毫秒；编码器是否同时接相机行触发；`lines_per_pulse`。
4. RUN / PAUSE / STOP 对给料、输送、喷阀气源的具体动作。
5. 心跳超时后的安全动作范围（只停阀，还是停给料/输送）。
6. 9 个给料速度的含义与范围。
7. 是否需要主机下发"吹气类别"（不需要：决策在算力盒完成，下位机只收喷头+行号）。
8. 多板扩展时的地址分配与喷头全局编号。
9. LEN 保护：头部 CRC8 还是按 CMD 限定 LEN 的合法值（§2）。
10. STATUS `faults` 位图与 §7 事件码的映射是否为 bit n ↔ code n（§6）。
11. 上行帧（STATUS / EVENT / COUNTERS）的 ADDR 取值（主机侧头部预检只接受 0x01 / 0xFF）。
12. HEARTBEAT 应答 NACK（`result≠0` 的 1 字节）的语义确认：fault 态是否回 5；主机按"链路活着但设备故障"处理，保持连接不重连。
13. STATUS 主动上报是否统一带 result 字节（20 B）；主机当前兼容 19 B 裸负载（§6），定稿后可去掉兼容分支。
14. PAUSE 期间输送带是否停、编码器计数是否冻结：主机恢复（PAUSE → RUN）时**不发 SYNC、不重置行号**（§8），前提是暂停期间行号与编码器仍同步；若下位机 PAUSE 时皮带继续走，则恢复时必须重新 SYNC（后端需改为恢复时也 SYNC + 行号归零）。
