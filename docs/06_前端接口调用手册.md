# 矿石分选机 HMI 接口调用手册（v1）

本手册面向 HMI 前端，只讲**接口怎么调、传什么参数、返回什么、出错怎么判断**。
接口版本 v1，对应后端版本 0.1.0，更新日期 2026-11-03。

随手册附带 `openapi.json`（OpenAPI 3），可导入 Apifox / Postman / Swagger Editor 直接生成请求和 TypeScript 类型。
两点说明：

- `openapi.json` 里每个接口都自动带了 `422` 响应，**实际不会出现 422**：参数格式错误统一返回 `400`，体为 §1.3 的错误格式。
- 两条 WebSocket 不在 `openapi.json` 里，消息格式只在本手册 §4。

后端运行时，浏览器打开 `http://<算力盒IP>:8000/api/v1/docs` 可在线发请求看响应（Swagger UI）。

## 1. 基本约定

### 1.1 地址

| 用途 | 地址 |
|---|---|
| REST 基地址 | `http://<算力盒IP>:8000/api/v1` |
| WebSocket | `ws://<算力盒IP>:8000/api/v1/ws/events`、`ws://<算力盒IP>:8000/api/v1/ws/preview/{camera_id}` |
| 图片等静态文件 | `http://<算力盒IP>:8000/static/...` |

下文所有路径都省略 `/api/v1` 前缀。响应里的 `image_url` / `thumb_url` 是站点相对路径（如 `/static/snapshots/xxx.jpg`），前端自行拼上 `http://<算力盒IP>:8000`。

没有鉴权（局域网内部署）。联调环境已放开跨源访问，前端开发服务器（如 `http://localhost:5173`）可直接调用；正式部署时 HMI 与后端同源，若最终要独立部署前端站点，提前告知后端把来源加入白名单。

### 1.2 格式

- 请求与响应均为 `application/json; charset=utf-8`。
- 时间字符串为 ISO 8601 带时区，如 `2026-10-24T16:40:00+08:00`。
- 图像尺寸单位为像素；枚举值一律小写字符串。
- `GET` 请求没有请求体；`POST` 接口若标注"体可空"，可以不传体或传 `{}`。

### 1.3 错误格式与错误码

成功：2xx + JSON 体。失败：4xx / 5xx + 固定结构：

```json
{"error": {"code": "PARAM_OUT_OF_RANGE", "message": "开阀时间超出范围 0~255", "detail": {"field": "open_time", "input": 300, "range": [0, 255]}}}
```

`message` 是可直接展示的中文；`detail` 随 `code` 不同，没有附加信息时为 `{}`。

| code | HTTP | 含义 | `detail` 常见内容 |
|---|---|---|---|
| `VALIDATION` | 400 | 参数格式 / 跨字段规则不通过 | 格式错误时 `{"errors": [...]}`；其它见各接口 |
| `PARAM_OUT_OF_RANGE` | 400 | 单个数值越界 | `{"field", "input", "range": [lo, hi]}` |
| `NOT_FOUND` | 404 | 对象不存在（模型 / 样本 / 任务 / 相机 / 路径） | 视接口而定 |
| `CONFLICT` | 409 | 当前状态不允许该操作，或对象已存在 / 正被任务占用 | `{"state", "reasons": [...]}` 或 `{"job_id"}` |
| `DEVICE_OFFLINE` | 503 | 相机或下位机离线 | `{"camera_id"}` 或 `{"device": "mcu"}` |
| `MCU_NACK` | 502 | 下位机拒绝了指令 | `{"result", "cmd"}` |
| `MCU_TIMEOUT` | 504 | 下位机未在时限内应答 | `{}` |
| `INTERNAL` | 500 | 后端内部错误 | `{}` |

前端处理建议：按 `code` 分支，`message` 直接提示用户；`CONFLICT` 时再看 `detail.reasons`（枚举见 §3.2）。

### 1.4 写操作的幂等 `request_id`

所有写操作（POST / PUT / PATCH / DELETE）建议带 `request_id`：字符串，**不超过 128 字符**，放在 JSON 体顶层或请求头 `X-Request-Id`（头优先）。

- 同一 `(方法, 路径, request_id)` 在 60 s 内重复提交，后端**直接回放第一次的完整响应**（状态码、头、体），不会重复执行；回放响应带头 `X-Idempotent-Replay: 1`。
- 第一次失败（4xx / 5xx）的结果同样会被回放，不会"重试成功"。
- 用途：按钮连点、网络超时重试。**一次用户操作生成一个 `request_id`，重试时沿用同一个**；换一次新操作就换新的 id。
- `request_id` 不算业务字段，不会出现在 `applied` 等返回里。

### 1.5 状态来源与推送

- 后端是状态的唯一来源。HMI 启动时、以及 `/ws/events` 每次重连后，先 `GET /state` 全量同步，之后靠 `/ws/events` 增量更新；不要在前端自行推演状态。
- 点击操作按钮前的"确认框"由 HMI 自己做，后端不做二次确认。

### 1.6 枚举

| 字段 | 取值 |
|---|---|
| `run_state` | `stopped` \| `running` \| `paused` \| `sampling` \| `fault` |
| `awb_mode` | `off` \| `once` \| `continuous` |
| `trigger` | `internal` \| `encoder` |
| `job.status` | `queued` \| `running` \| `succeeded` \| `failed` \| `cancelled` |
| `job.type` | `capture` \| `train` \| `deploy` \| `valve_test` \| `backup` |
| `params` 分组 `section` | `valve` \| `clean` \| `feed` \| `outputs` \| `blow` \| `capture` |
| `capture.bg_mode` | `column` \| `color` |
| 预览 `mode` | `full` \| `edges` |

### 1.7 长操作 = 任务

训练、采样、部署、备份、喷阀循环检测都是后台任务：接口立即返回 `{"job_id": "..."}`（训练为 202，其余 200），进度与结果通过 `GET /jobs/{job_id}`（§3.8）或 `/ws/events` 的 `job` 事件获取，可用 `POST /jobs/{job_id}/cancel` 取消。

### 1.8 请求封装示例（JS）

```js
const BASE = `http://${host}:8000/api/v1`;

// requestId：一次用户操作生成一次（crypto.randomUUID()），重试时传同一个
async function api(method, path, body, requestId) {
  const headers = { "Content-Type": "application/json" };
  if (requestId) headers["X-Request-Id"] = requestId;
  const res = await fetch(BASE + path, {
    method, headers, body: body === undefined ? undefined : JSON.stringify(body),
  });
  const data = await res.json();
  if (!res.ok) throw data.error;        // {code, message, detail}
  return data;
}

// 用法
const state = await api("GET", "/state");
await api("PUT", "/params/valve", { open_time: 200 }, crypto.randomUUID());
```

## 3. REST 接口

下文"体可空"= 请求体可省略或只含 `request_id`。

### 3.1 系统与状态

#### GET /health

存活探针。→ `{"ok": true, "version": "0.1.0"}`

#### GET /state

全量状态快照（启动与 WS 重连后调用）。

```json
{
  "time": "2026-10-24T16:40:00+08:00",
  "uptime_total_s": 864000,
  "run_state": "running",
  "deployed_model_id": 1,
  "cameras": [{"id": 1, "connected": true, "streaming": true, "line_rate_hz": 9000, "chunks_total": 63000, "dropped_chunks": 0, "reconnects": 0, "errors": 0, "chunks_per_s": 17.5}],
  "mcu": {"connected": true, "state": "running", "last_heartbeat_ms": 120, "rtt_ms": 3, "encoder_count": 123456, "faults": [], "queue_len": 0, "belt_speed": 0, "pressure": null, "counters": {"eject_rx": 0, "eject_done": 0, "eject_dropped": 0, "period_ms": 0}, "reconnects": 0, "ack_timeouts": 0},
  "faults": [],
  "jobs": [{"job_id": "j-20261024-0001", "type": "train", "status": "running", "progress": 0.42, "stage": "epoch 8/30", "model_id": 2}],
  "stats": {"particles_per_min": 1200, "blown_per_min": 300, "per_class_per_min": {"A": 500, "B": 400, "C": 300, "D": 0, "E": 0, "F": 0, "G": 0},
            "chunk_latency_ms_p50": 23.5, "chunk_latency_ms_p99": 61.0, "chunk_latency_ms_max": 74.2,
            "chunks_total": 63000, "dropped_chunks": 0, "particles_total": 72000, "blown_total": 18000,
            "per_class_total": {"A": 30000, "B": 24000, "C": 18000, "D": 0, "E": 0, "F": 0, "G": 0},
            "since": "2026-10-24T15:40:00+08:00", "elapsed_s": 3600.0},
  "pipeline": {"...": "内部诊断信息，界面不需要"},
  "version": "0.1.0"
}
```

| 字段 | 说明 |
|---|---|
| `time` | 算力盒当前时间（底栏显示用） |
| `uptime_total_s` | 设备累计运行时长（秒） |
| `run_state` | 运行状态枚举 |
| `deployed_model_id` | 当前部署模型编号，无则 `null` |
| `cameras[]` | 每台相机：`connected` 在线、`streaming` 正在出流、`line_rate_hz` 行频、块计数与丢块数、重连次数、错误数、每秒块数 |
| `mcu` | 下位机：`connected`、`state`、`last_heartbeat_ms` 距上次心跳毫秒、`rtt_ms`、`encoder_count` 编码器计数、`faults` 故障文字列表、`belt_speed`、`pressure`（无则 `null`）、计数器、`reconnects`、`ack_timeouts` |
| `faults[]` | 当前故障：`{"code", "since", "detail"}`，见下表 |
| `jobs[]` | 进行中任务，元素同 `GET /jobs/{id}` |
| `stats` | 运行统计：`*_per_min` 为最近 60 s 折算的整数；`chunk_latency_ms_*` 为处理延时（float）；`*_total` 与 `since` / `elapsed_s` 自本次开始运行累计，停止后仍保留上次的值；`per_class_*` 总是包含全部已配置类别（未出现为 0） |
| `pipeline` | 内部诊断，忽略即可；没有在跑时为 `null` |
| `version` | 后端版本号 |

**故障码 `faults[].code`**

| code | 含义 | 何时清除 |
|---|---|---|
| `CAMERA_{id}_DISCONNECTED` | 相机打开失败 / 掉线 / 开流失败 | 相机重连后 |
| `CAMERA_{id}_TIMEOUT` | 运行中相机在线但持续无图像 | 再次收到图像后，或 `POST /run/stop` |
| `MCU_DISCONNECTED` | 下位机断线 / 心跳或应答超时 | 重连后 |
| `MCU_EVENT_xxxx` | 下位机上报的严重事件（后四位为十六进制事件码） | 下位机重连后 |
| `MCU_FAULT_xxxx` | 下位机故障位（后四位为十六进制位号）；下位机故障同时以 `mcu.faults` 文字列表给出，界面两者都显示 | 位清除后 |
| `PIPELINE_ERROR` | 识别流水线连续处理失败 | 操作员 `POST /run/stop`（视为确认） |
| `CLASSIFIER_ERROR` | 分类器连续推理失败 | 重新部署模型后 |
| `MODEL_LOAD_FAILED` | 开机加载已部署模型失败，`deployed_model_id` 被清空 | 重新部署后 |

任何故障置位时 `run_state` 变为 `fault`，后端自动停机；全部故障清除后回到 `stopped`，需要操作员重新点"运行"。

#### GET /system/info

→ `{"version", "hostname", "disk_total_mb", "disk_free_mb", "cpu_percent", "mem_percent", "gpu_percent": float|null, "temperatures_c": {传感器名: ℃}, "ips": {网口名: ["IPv4", ...]}, "preview_max_fps": 10, ...}`
其余字段为诊断信息。`preview_max_fps` 是预览 WebSocket `fps` 参数的上限（§4.2）。

#### POST /system/save

体可空。→ `{"saved": true, "backup_path": "..."}`。
参数在每次修改时已即时保存，此接口用于顶栏"保存"按钮：刷新运行时长并导出一份备份。

#### POST /system/shutdown　/　POST /system/reboot

体可空。→ `{"accepted": true, "action": "poweroff" | "reboot"}`。
后端先停机（取消采样、停止运行）再在约 2 s 后执行关机 / 重启。联调环境下不会真的关机，响应相同。

### 3.2 运行控制

#### POST /run/start　/　POST /run/pause　/　POST /run/stop

体可空。成功 → `{"run_state": "running", "mcu_ack": true}`（`run_state` 为操作后的状态）。

- `start`：`stopped → running`（清零统计、同步下位机、启动识别）；`paused → running` 只恢复吹气，不重新同步。
- `pause`：`running → paused`，停止吹气但继续识别与统计。
- `stop`：任意状态 → `stopped`。`sampling` 状态下会先取消采集任务（最多等 3 s）再停止。
- **`fault` 状态下 `stop` 不报错**：返回 200 `{"run_state": "fault", "mcu_ack": true|false}`，故障不会因此清除，恢复后状态自动回到 `stopped`。
- 重复调用（running 再 start、paused 再 pause、stopped 再 stop）返回 200 当前状态，不报错。

失败 → 409 `CONFLICT`，`detail = {"state": "当前状态", "reasons": [...]}`，`reasons` 取值：

| reason | 含义 |
|---|---|
| `NO_MODEL_DEPLOYED` | 没有已部署模型（先在图像页训练并部署） |
| `CAMERA_DISCONNECTED` | 相机离线或开流失败（`detail.camera_id`） |
| `MCU_DISCONNECTED` | 下位机离线 |
| `SAMPLING_IN_PROGRESS` | 正在采样 |
| `IN_FAULT` | 处于故障状态 |
| `ALREADY_RUNNING` | 已在运行 |
| `NOT_RUNNING` | 不在运行（如 stopped 下 pause） |
| `NOT_SAMPLING` | 不在采样 |
| `BACKGROUND_NOT_LEARNED` | 某相机的背景尚未学习（现场调试项，`detail.camera_id`） |

#### GET /run/stats

→ `GET /state` 的 `stats` 全部字段 + `since_start`（`{"since", "elapsed_s", "chunks_total", "dropped_chunks", "particles_total", "blown_total", "per_class_total"}`，自本次开始运行累计）+ `pipelines`（内部诊断，忽略）。运行中更推荐用 WS `stats` 事件（每秒一条）。

### 3.3 参数

#### GET /params

六个分组的当前值 + `limits`（**输入范围以此为准，不要在前端写死**）：

```json

  "valve": {"open_time": 255, "hold": 255, "reblow": 20, "delay": 376},
  "clean": {"time": 20, "period": 200, "count": 5, "enabled": false},
  "feed": {"speeds": [50, 50, 50, 50, 50, 50, 50, 50, 50]},
  "outputs": {"conveyor": false, "valve": false, "feeder": false},
  "blow": {"classes": ["C"], "min_confidence": 128, "size_min": 0, "size_max": 255},
  "capture": {"bg_mode": "column", "bg_color": [0, 0, 255], "bg_threshold": 40.0, "erode_px": 1, "dilate_px": 2, "min_area_px": 400, "max_area_px": 2000000, "margin_px": 8, "split_touching": false, "bg_learn_frames": 20, "bg_adapt_rate": 0.0},
  "limits": {
    "valve": {"open_time": [0, 255], "hold": [0, 255], "reblow": [0, 50], "delay": [0, 800]},
    "clean": {"time": [0, 200], "period": [0, 200], "count": [0, 5]},
    "feed": {"speed": [0, 100], "count": 9},
    "valve_test": {"hole": [1, 64]},
    "blow": {"min_confidence": [0, 255], "size_min": [0, 255], "size_max": [0, 255]},
    "capture": {"bg_threshold": [0, 255], "erode_px": [0, 50], "dilate_px": [0, 50], "min_area_px": [0, 16000000], "max_area_px": [1, 16000000], "margin_px": [0, 200], "bg_learn_frames": [1, 1000], "bg_adapt_rate": [0, 0.1]}
  }
}
```

| 分组 | 字段 | 类型 / 规则 |
|---|---|---|
| `valve` 喷阀 | `open_time` 开阀时间、`hold` 保持、`reblow` 补吹、`delay` 延时 | 整数，范围见 `limits.valve` |
| `clean` 清灰 | `time`、`period`、`count` | 整数，范围见 `limits.clean` |
| | `enabled` | 布尔，清灰开关 |
| `feed` 给料 | `speeds` | 整数数组，**长度必须等于 `limits.feed.count`**，每项范围 `limits.feed.speed` |
| `outputs` 输出 | `conveyor` 输送、`valve` 喷阀、`feeder` 给料 | 布尔 |
| `blow` 吹气 | `classes` | 需要吹出的类别名数组（取自 `GET /config/classes`） |
| | `min_confidence`、`size_min`、`size_max` | 整数 0~255；`size_min ≤ size_max` |
| `capture` 采集 | `bg_mode` | `column` 逐列背景 \| `color` 固定颜色 |
| | `bg_color` | `[r, g, b]`，各 0~255 |
| | `bg_threshold` | 小数，`limits.capture.bg_threshold` |
| | `erode_px`、`dilate_px`、`min_area_px`、`max_area_px`、`margin_px`、`bg_learn_frames` | 整数，范围见 `limits.capture` |
| | `bg_adapt_rate` | 小数，`limits.capture.bg_adapt_rate` |
| | `split_touching` | 布尔，是否切分粘连颗粒 |

`limits.valve_test.hole` 是喷阀检测孔位范围（`[1, 相机数 × 每相机喷头数]`）。

#### PUT /params/{section}

`section ∈ valve | clean | feed | outputs | blow | capture`，其它值 → 404。

- 请求体：该分组的**部分或全部字段**（部分更新），如 `PUT /params/valve` 体 `{"open_time": 200, "request_id": "..."}`。
- 响应：`{"applied": {该分组全部当前值}, "mcu_ack": true | false | null, "warnings": []}`
  - `mcu_ack = true`：已保存并被下位机确认；
  - `mcu_ack = null`：该分组不需要下发下位机（`blow`、`capture`），已保存即生效；
  - `mcu_ack = false`：已保存但下位机未确认（超时 / 断线），`warnings` 有说明；下位机重连后后端自动补发，最终结果以 WS `param_sync` 事件为准。
- 越界 → 400 `PARAM_OUT_OF_RANGE`（单字段）或 `VALIDATION`（跨字段规则，如 `speeds` 长度、`size_min > size_max`），整组都不会被应用。
- 下位机拒绝 → 502 `MCU_NACK`，参数回滚为修改前的值。
- `blow` 立即作用于运行中的识别；`capture` 修改后对运行中的识别热生效。

### 3.4 喷阀检测

只允许在 `stopped` 或 `fault` 状态下使用；`running` / `paused` 下 → 409，`detail.reasons = ["ALREADY_RUNNING"]`；`sampling` 下 → `["SAMPLING_IN_PROGRESS"]`。点"运行"会自动结束进行中的循环检测。

| 接口 | 请求体 | 响应 |
|---|---|---|
| `POST /valve/test/single` | `{"hole": 12}`，范围 `limits.valve_test.hole`，越界 400 | `{"accepted": true}`；孔位会被记住 |
| `POST /valve/test/cycle` | `{"from": 1, "to": 64, "interval_ms": 200}`；`from`/`to` 同孔位范围，`from > to` → 400 `VALIDATION`；`interval_ms` 1~65535，默认 200 | `{"job_id": "..."}`（任务 `type=valve_test`） |
| `POST /valve/test/stop` | 体可空 | `{"stopped": true}` |
| `POST /valve/reset` | 体可空 | `{"accepted": true, "mcu_ack": true}` |

#### PUT /cameras/{camera_id}/params

下发（部分更新）。可写字段：`awb_mode / exposure_us / width / offset_x / height / runtime_chunk_lines / start_px / end_px / line_rate_hz / trigger`，传其它字段 → 400 `VALIDATION`。

- 响应：`{"applied": {全部当前字段}, "warnings": [...]}`。
- 先整体校验：任一字段越界 → 400 `PARAM_OUT_OF_RANGE`，**整组不保存、不下发**。
- 相机会把部分值按步进对齐，`applied` 里是实际生效值，并在 `warnings` 说明（如 `相机按步进对齐了部分参数: exposure_us → 50.5`）；界面下发后用 `applied` 回填输入框。
- 相机离线时**不报 503**：校验通过即保存，重连后自动下发，响应 200 且 `warnings` 含 `相机离线，参数已保存，连接后生效`。
- 运行中修改 `width / offset_x / height / runtime_chunk_lines` 需要重新开始运行才生效（前三者会在 `warnings` 提示；只改 `runtime_chunk_lines` 时无 warning，界面自行提示）。
- `start_px / end_px` 修改后立即影响喷头映射，无需重启。

#### POST /cameras/{camera_id}/awb-once

体可空。做一次白平衡并把 `awb_mode` 锁定为 `off`。→ `{"applied": true}`；相机离线 → 503。

#### GET /cameras/{camera_id}/nozzle-map

像素 → 喷头映射表（功能页校验用）：

```json
{"start_px": 0, "end_px": 4096, "nozzles": 64, "quotient": 64, "remainder": 0,
 "ranges": [{"nozzle": 1, "px_from": 0, "px_to": 63}, {"nozzle": 2, "px_from": 64, "px_to": 127}]}
```

#### POST /cameras/{camera_id}/snapshot

单次采集。体（均可省略）：

| 字段 | 说明 |
|---|---|
| `height` | 采集行数，1~4096，缺省取相机当前 `height` |
| `max_width` | 图片文件按此等比缩放，16~16384，默认 2000 |
| `overlay` | `true` 时叠画分割框（调采集设置用），并额外返回 `count` 颗粒数 |

→ `{"image_url": "/static/snapshots/cam1_20261024_164012_123456.jpg", "width": 4096, "height": 4096, "warnings": [], "count": 37}`

- `width / height` 是原图尺寸，文件本身按 `max_width` 缩放。
- 停止状态下直接向相机采集；运行 / 采样中不打断识别，用连续图像拼到请求高度，时限内拼不满时 `height` 会小于请求值并在 `warnings` 说明。
- 相机离线 → 503；`overlay=true` 且背景未学习 → 409 `CONFLICT`，`detail.reasons = ["BACKGROUND_NOT_LEARNED"]`。
- 快照文件只保留最近 50 张，拿到 `image_url` 后应尽快加载显示。

| `GET /models/{model_id}/metrics` | — | 训练指标全文：混淆矩阵 `{"labels": [...], "matrix": [[...]]}`、每类精确率 / 召回率 / F1 / 样本数、训练曲线 |

### 3.7 样本采集与管理

#### POST /models/{model_id}/classes/{cls}/capture

|---|---|

| `max_samples` | 最多采集张数，1~100000，默认 200 |

### 3.8 训练与任务

#### POST /models/{model_id}/train

| type | result |

| `train` | `{"metrics_summary": {"val_accuracy", "macro_f1"}, "artifacts": {...}, "classes": [...], "epochs": 18, "duration_s": 132.5}`；若触发了自动重新部署另含 `redeploy_job_id`，未能触发含 `redeploy_error` |

## 4. WebSocket

### 4.1 事件流 `/ws/events`

`ws://<算力盒IP>:8000/api/v1/ws/events`

连接成功后**立即收到一条 `state` 全量事件**（结构同 `GET /state`，可代替重连后的一次 GET），之后按需推送。所有消息都是文本 JSON：`{"type": "...", "ts": "...", "data": {...}}`。

| type | 触发时机 | data |
|---|---|---|
| `state` | 状态迁移、故障置位 / 清除、部署模型切换、类别配置修改，以及每 5 s 心跳 | 同 `GET /state` |
| `stats` | 运行中每 1 s | 同 `state.stats` |
| `job` | 任务创建 / 开始 / 进度 / 完成 / 失败 / 取消 | 同 `GET /jobs/{id}`（同一任务进度事件最快 0.1 s 一条，结束事件必达） |
| `capture_sample` | 采样切出一张样本 | `{"model_id": 1, "class": "A", "sample": {样本项，同样本列表元素}, "count": 57}` |
| `param_sync` | 参数下发下位机的最终结果 | `{"section": "valve", "mcu_ack": true, "error": null}` |
| `fault` | 故障产生 / 清除 | `{"code": "MCU_DISCONNECTED", "active": true, "detail": "..."}` |
| `mcu` | 下位机状态变化 | 同 `state.mcu` |
| `ping` | 每 5 s | 无，见下 |

**存活检测（必须实现）**：服务端每 5 s 发文本 `{"type": "ping", "ts": "..."}`，客户端必须回文本 `{"type": "pong"}`；连续 15 s 没有收到任何客户端消息，服务端以 1001 关闭连接。浏览器的 WebSocket 对象不暴露协议层 pong，所以一定要在应用层回。

其它要点：

- 断线后前端自行重连（建议 1 s 后）；重连后首条 `state` 就是全量，直接整体替换本地状态。
- `state / stats / mcu` 是全量型，收到就整体替换；`job / capture_sample / param_sync / fault` 是增量型，按 id 合并。
- 服务端每连接缓冲 200 条，消费太慢会丢最旧的，所以处理函数要轻。

```js
function connectEvents() {
  const ws = new WebSocket(`ws://${host}:8000/api/v1/ws/events`);
  ws.onmessage = (ev) => {
    const msg = JSON.parse(ev.data);
    switch (msg.type) {
      case "ping":           ws.send(JSON.stringify({ type: "pong" })); break;
      case "state":          store.replaceState(msg.data); break;      // 全量
      case "stats":          store.setStats(msg.data); break;
      case "job":            store.upsertJob(msg.data); break;         // 按 job_id 合并
      case "capture_sample": store.appendSample(msg.data); break;
      case "param_sync":     store.setParamSync(msg.data); break;
      case "fault":          store.setFault(msg.data); break;
      case "mcu":            store.setMcu(msg.data); break;
    }
  };
  ws.onclose = () => setTimeout(connectEvents, 1000);
}
```

### 4.2 连续预览 `/ws/preview/{camera_id}`

`ws://<算力盒IP>:8000/api/v1/ws/preview/1?mode=full&fps=5&quality=70&max_width=1000&edge_px=500`

| 查询参数 | 范围 | 默认 | 说明 |
|---|---|---|---|
| `mode` | `full` \| `edges` | `full` | `full` 整幅等比缩放到 `max_width`；`edges` 取左右两段 `[0, edge_px)` 与 `[w-edge_px, w)` 横向拼成一幅（两段式显示） |
| `fps` | 1 ~ `preview_max_fps`（`GET /system/info`，默认 10） | 5 | 每秒帧数上限 |
| `quality` | 10~100 | 70 | JPEG 质量 |
| `max_width` | 16~16384 | 1000 | 仅 `full` 模式生效 |
| `edge_px` | 1 ~ 相机 `width` | 500 | 仅 `edges` 模式生效，输出宽度恒为 `2 × edge_px` |

**消息协议**：每帧两条消息，先文本 `{"type": "frame", "seq": 12, "w": 1000, "h": 512, "start_px": 0, "end_px": 4096, "ts": "..."}`（`w / h` 为输出图尺寸），紧接一条**二进制**消息（JPEG）。

- `edges` 模式会在 `start_px` / `end_px` 位置画 2 px 白色竖线，落在两段之外的不画。
- 服务端按 `fps` 限频，每个时隙只发最新一帧，不会堆积。
- 参数越界**不夹断、直接拒绝**：连接建立后先收到文本 `{"type": "error", "code": "PARAM_OUT_OF_RANGE" | "VALIDATION" | "NOT_FOUND", "message": "...", "detail": {...}, "ts": "..."}`，随后以 1008 关闭。`PARAM_OUT_OF_RANGE` 的 `detail = {"field", "input", "range"}`；`NOT_FOUND`（相机不存在）`detail = {"camera_id"}`。
- 相机离线：收到 `{"type": "error", "code": "DEVICE_OFFLINE", ...}` 后以 1011 关闭。
- 不需要回 pong；客户端关闭连接即停止预览。运行 / 采样期间预览不影响识别。

```js
const ws = new WebSocket(`ws://${host}:8000/api/v1/ws/preview/1?mode=edges&fps=5&edge_px=500`);
ws.binaryType = "blob";
let meta = null;
ws.onmessage = (ev) => {
  if (typeof ev.data === "string") {
    const msg = JSON.parse(ev.data);
    if (msg.type === "error") { showError(msg); return; }   // 服务端随后会关闭连接
    meta = msg;                                             // 下一条二进制就是这帧的 JPEG
    return;
  }
  const url = URL.createObjectURL(ev.data);
  img.onload = () => URL.revokeObjectURL(url);
  img.src = url;
};
```

| `/static/models/{id}/thumbs/{cls}/*.jpg` | 样本缩略图（已删除的在 `/static/models/{id}/thumbs/.trash/{cls}/`） |
| `/static/models/{id}/samples/{cls}/*.png` | 样本原图，带透明通道（已删除的同样在 `.trash/` 段下） |
| `/static/snapshots/*.jpg` | 单次采集图，只保留最近 50 张 |
| `/static/previews/*.jpg` | 采集设置预览图，只保留最近 50 张 |

路径一律取自接口返回的 `image_url` / `thumb_url`，不要自己拼文件名；上述之外的路径返回 404。

## 6. 推荐调用流程

**启动 / 重连**：`GET /health` → `GET /state` → 连 `/ws/events`（首条 `state` 覆盖本地）→ `GET /params`、`GET /cameras`、`GET /config/classes`、`GET /models`。

**运行**：`POST /run/start` → 成功后靠 `stats` 事件刷新统计；409 时按 `detail.reasons` 提示（最常见 `NO_MODEL_DEPLOYED`）。

**从零到可运行（图像页）**：`POST /models/1` 新建 → 对至少 2 个类别 `POST /models/1/classes/{cls}/capture` 采样（看 `capture_sample` 事件刷新缩略图，可 `POST /jobs/{id}/cancel` 提前结束）→ `POST /models/1/train`（看 `job` 事件进度）→ `POST /models/1/deploy`（看 `job` 事件）→ `GET /models/current` 确认 → `POST /run/start`。

**相机调参（功能页）**：`GET /cameras/{id}/params` 回填 → 修改后 `PUT /cameras/{id}/params` → 用 `applied` 回填、`warnings` 提示 → `POST /cameras/{id}/snapshot` 或开 `/ws/preview/{id}?mode=edges` 查看效果。

**参数页**：`GET /params` 回填并用 `limits` 设置输入范围 → `PUT /params/{section}` → 用 `applied` 回填；`mcu_ack=false` 时提示"已保存，等待下位机确认"，以后续 `param_sync` 事件为准。
