# 01 技术选型与架构

状态：已与项目负责人确认的选型（2026-10-24）。未确认项集中在 §11。

## 1. 范围

- 本服务跑在算力盒（图为 TW-T201P / Jetson Orin Nano 8G）上，是整机的"大脑"：采集、识别、决策、对下位机发令、对 HMI 提供接口、管理样本与模型。
- 阶段一目标：**验证识别准确率**（采集 → 切图 → 人工标定 → 训练 → 跨批次评估），喷阀与下位机先用模拟实现。
- 不包括：HMI 界面（其他同事）、下位机固件、机械气路。

## 2. 已拍板的选型

| 选型项 | 决定 | 备注 |
|---|---|---|
| 运行环境 | JetPack 6.x（L4T r36、Ubuntu 22.04、Python 3.10、CUDA 12、TensorRT 8.6/10.x 视小版本）；Orin Nano **8G** | 版本以 `cat /etc/nv_tegra_release` 为准 |
| 语言 | **Python 为主**；热点路径（采集/分割）测出瓶颈再以 C++ 扩展（pybind11）或独立进程替换 | 一路相机 9 kHz 行频 ≈ 110 MB/s，按 512 行分块 ≈ 17.6 块/s，Python + OpenCV 可承受 |
| 相机接入 | 海康 **MVS SDK（Linux aarch64）** 官方 Python 封装；抽象 `Camera` 接口 + Mock | 备选 Aravis |
| 采集方式 | RGB8；采样/标定用整帧（高 4096），**运行时按 256~512 行分块流水**；生产用**编码器行触发**，阶段一可内触发固定行频 | 行频不够时切 Bayer8（28 kHz）+ GPU 解拜耳 |
| 分割切图 | OpenCV 经典法（逐列背景模型 → 颜色距离阈值 → 开闭运算 → 连通域 → 带 mask 裁切），粘连可选分水岭 | 参数即 HMI"采集设置" |
| 分类器 | **CNN 微调**：torchvision ResNet18（默认）/ MobileNetV3-Large（轻量可选），ImageNet 预训练权重离线内置；固定训练配方，一键训练 | 算法接口可插拔，后续可加"冻结嵌入 + 线性头"快速模式 |
| 推理 | ONNX → **TensorRT FP16** 引擎（算力盒现场生成）；PyTorch FP16 兜底 | TensorRT Python API，用 torch 张量做显存缓冲，不引入 pycuda |
| 训练执行 | 独立子进程（`multiprocessing` spawn），低优先级；结束后若该模型为当前方案则自动重新部署 | 训练崩溃不影响主服务 |
| 进程/线程 | 单主服务进程（systemd）：asyncio API + 流水线线程（采集 / 处理 / 下位机发送）+ 训练子进程 | GIL 争用超标再拆进程 + 共享内存 |
| HMI 接口 | **HTTP REST + WebSocket（FastAPI）**，JSON；缩略图/图片走静态 URL；OpenAPI 自动文档作为契约 | 端口默认 8000 |
| 下位机链路 | **以太网 TCP 长连接**（下位机作 server，后端重连），TCP_NODELAY + keepalive + 应用层心跳；二进制帧 + 序列号 + CRC16 | 备选 CAN；UART 仅应急 |
| 喷阀时序分工 | 后端给出"喷头区间 + 颗粒经过相机的行号"，**下位机按编码器计数换算开阀时刻**；延时/开阀/维持/重吹参数在下位机执行 | Linux 非实时，不自己计时 |
| 模型/类别数 | **可配置**（默认 7 个模型、类别 A~G） | HMI 按配置渲染 |
| 数据存储 | NVMe 上文件系统目录 + JSON 元数据；配置 JSON + pydantic 校验 | 样本上十万再加 SQLite 索引 |
| 开发/测试 | Mock 相机（回放图片目录）+ Mock 下位机；pytest；整套可在 Mac/PC 跑 | Claude Code 无硬件可开发自测 |
| 部署 | venv + 锁定版本 requirements + systemd（Restart=always）+ journald | 不用 Docker |

## 3. 网络拓扑

```
                 ┌──────────────────────────── 算力盒 TW-T201P ────────────────────────────┐
 海康线阵相机 ───┤ eth(5G)  192.168.10.1/24  ←直连，MTU 9000，静态 IP，相机 192.168.10.10   │
                 │                                                                         │
 工业交换机 ─────┤ eth(1G)  192.168.1.10/24                                                │
   ├── HMI 工控机 192.168.1.20   ←→  HTTP :8000 / WebSocket                                 │
   └── 下位机主控 192.168.1.30   ←→  TCP :5000（下位机 server）                               │
                 └─────────────────────────────────────────────────────────────────────────┘
```

- 相机独占一个网口：满行频 ≈ 885 Mbps，和别的流量共口必丢包；5G 口有裕量，后续多相机可在 5G 口下挂交换机。
- 全部静态 IP，写在 `config/*.yaml`；Type-C 口的 192.168.55.1 是刷机口，不用。
- 系统调优：`ip link set <eth> mtu 9000`、`sysctl net.core.rmem_max=26214400 net.core.rmem_default=26214400`、`nvpmodel -m 0`、`jetson_clocks`；SDK 侧开启 GVSP 丢包重传、合适的 `GevSCPSPacketSize`（巨帧下 8164）与较大的图像缓存节点数。

## 4. 软件架构

### 4.1 模块图

```
                         ┌───────────────── api/ (FastAPI) ─────────────────┐
  HMI ◄── REST / WS ───► │ routes_system  routes_models  routes_samples      │
                         │ routes_params  routes_camera  routes_run  ws      │
                         └───────────────┬───────────────────────────────────┘
                                         │ 调用（线程安全的服务对象）
     ┌──────────────┬────────────────────┼─────────────────┬──────────────────┐
     ▼              ▼                    ▼                 ▼                  ▼
 config/        data/store          runtime/            ml/              mcu/
 参数与持久化     模型目录、样本        状态机 + 流水线      训练子进程、          协议、TCP 链路、
                 软删除/撤销/备份      采集→分割→分类→决策   导出、TRT 推理       心跳、重连、Mock
                                         │
                       ┌─────────────────┼──────────────────┐
                       ▼                 ▼                  ▼
                   camera/            vision/            vision/nozzle
                   Hik SDK / Mock     segment, stitch,   像素→喷头、行号
                   分块帧流            preprocess
```

### 4.2 运行时数据流（分选模式）

```
相机 SDK 回调（512 行 × 4096 × RGB）
  → 环形队列（丢块计数）
  → 处理线程：
      拼接上一块尾部 overlap 行 → 逐列背景差分 → 阈值 → 开/闭运算 → 连通域
      → 跨块去重规则（见 §5.2）→ 每颗矿石：bbox、质心 x、尾沿行号、面积、带 mask 的小图
      → 统一预处理（去背景、补方、缩放、归一化）→ 批量推理（TensorRT）→ 概率
      → 决策：类别 ∈ 吹气类别集合 且 置信度 ≥ 阈值 且 面积 ∈ [min,max] → 吹
      → 喷头映射：质心 x → 喷头编号区间（§5.4）
  → 下位机发送线程：EJECT 帧（行号 + 喷头区间）合并为每块一帧批量发送
  → 统计：每类计数、吹气计数、块处理耗时、丢块数 → WS 每秒推送
```

采样模式与分选模式共用采集与分割，只是分割出的小图进样本库而不进分类器。

### 4.3 状态机

```
 boot → init(自检：相机连接、下位机握手、加载当前模型)
   ├─ 自检通过 且 auto_run_on_boot → running
   └─ 否则 → stopped（faults 列表说明原因）

 stopped ──start──► running ──pause──► paused ──start──► running
    ▲                 │                   │
    └──────stop───────┴────────stop───────┘
 stopped/paused ──capture job──► sampling ──job 结束──► 回到原状态
 任意状态 ──相机掉线 / 下位机心跳超时 / 流水线异常──► fault（自动重连成功后回到 stopped，需人工 start）
```

- `running`：给料 + 输送 + 喷阀使能，识别并下发喷阀；`paused`：停给料、不喷，输送是否停由下位机策略决定（TBD）；`stopped`：全停。
- 采样（sampling）要求当前为 stopped/paused，且独占相机；训练（train job）可在任意状态发起，在子进程中以低优先级执行。

## 5. 识别管线设计

### 5.1 采集
- `Camera` 接口：`open/close`、`get/set_params`（曝光、白平衡模式、宽、高、OffsetX、行频、触发源）、`start_stream(chunk_lines)`、`frames()` 迭代器（产出 `Frame(seq, line_start, image[h,w,3], timestamp)`）、`snapshot(height)`、`awb_once()`。
- 行号 `line_start` 是自 `SYNC` 以来的累计行计数（块序号 × 块高，SDK 丢块时按丢失块数补偿），是后端与下位机的共同时间轴（§5.5）。
- 白平衡策略：对白板/灰板做"一次"白平衡后**锁定**，禁止连续自动白平衡（会随矿石配比漂移，破坏颜色特征）。曝光同样固定。
- 行触发：编码器 → 相机 Line 输入 → 相机内分频/倍频得到行触发，保证每行对应固定皮带位移；阶段一无编码器时用内触发固定行频并记录带速。

### 5.2 分块与跨块去重
- 处理图 = 上一块尾部 `overlap` 行 + 当前块（`overlap` ≥ 最大矿石长度的行数，可配置，默认 256）。
- 只处理满足 `max_y ≥ overlap − 1` 且 **不触及处理图底边** 的连通域：
  - `max_y < overlap − 1` 的对象在上一块已完整处理过（上一块中它不触底）；
  - 触底的对象留到下一块（那时它会完整出现在 overlap 区域内）；
  - 对象长度超过 overlap 时会被截断，记 warning 并按截断处理。
- 单元测试：构造跨两块的合成颗粒，验证恰好处理一次。

### 5.3 分割（采集设置参数）
| 参数 | 含义 | 默认 |
|---|---|---|
| `bg_mode` | `column`（空皮带逐列背景，线阵推荐）/ `color`（固定背景色） | column |
| `bg_threshold` | 与背景的颜色距离阈值（Lab 空间） | 40 |
| `erode_px` / `dilate_px` | 腐蚀 / 膨胀像素（开运算去噪、闭运算填洞） | 1 / 2 |
| `min_area_px` / `max_area_px` | 连通域面积过滤 | 400 / 2 000 000 |
| `margin_px` | 裁切外扩 | 8 |
| `split_touching` | 距离变换 + 分水岭拆粘连 | false |
| `bg_learn_frames` | 学习背景用的空皮带帧数 | 20 |

输出 `Particle(bbox, centroid, area, trailing_line, crop_rgba)`，`crop_rgba` 的 alpha 即 mask。背景模型随"学习背景"操作更新并持久化，也可按配置缓慢自适应（只在无颗粒的列上更新）。

### 5.4 像素 → 喷头映射
- 输入：起始像素 A、结束像素 B、喷头数 N（默认 64）。`(B−A) = N·q + r`，前 ⌈r/2⌉ 个与后 ⌊r/2⌋ 个喷头各 q+1 像素，其余 q 像素（原始需求 §3）。
- 提供 `pixel_to_nozzle(x)`、`nozzle_ranges()`、给 HMI 的映射表；颗粒宽度跨多个喷头时输出 `[nozzle_first, nozzle_last]` 区间（可配置向两侧各扩 `nozzle_expand` 个）。
- 多相机时喷头全局编号 = `(camera_index) × N + 本地编号`，对应 HMI 的"孔位 0~768"。

### 5.5 时序模型
- 相机行触发与下位机编码器计数来自**同一编码器**：行号 ⇔ 皮带位移。`RUN` 时后端先发 `SYNC` 让下位机计数清零，随后重启采集使行号从 0 开始；两者零点误差由"延时"参数标定吸收。
- 后端对每颗矿石上报 `trailing_line`（尾沿行号）与喷头区间；下位机在 `encoder_count == trailing_line + delay` 时开阀，开阀时间/维持/重吹由下位机执行。
- 后端处理延迟只需小于"相机到喷阀的皮带行程时间"即可，不影响开阀精度。目标：512 行块端到端（块到达 → EJECT 发出）p99 < 80 ms。
- 无编码器（阶段一内触发）时行号按固定行频换算为时间，仅用于验证，不用于生产。

### 5.6 预处理（训练/推理共用）
1. RGBA 小图 → 背景像素置为常数（黑）；
2. 按长边补成正方形（常数填充）；
3. 缩放到 `image_size`（默认 160，可选 128/224）；
4. RGB、[0,1]、ImageNet 均值方差归一化；
5. 输出 `float16/32 CHW`。训练时的增广只在此函数之前做几何变换，颜色增广仅限小幅亮度/对比度（±10%），**禁止色相/饱和度抖动**（颜色是主要判据）。

## 6. CNN 训练与部署

### 6.1 模型
- 默认 `resnet18`（ImageNet 预训练，替换 fc → 类别数）；可选 `mobilenet_v3_large`。
- 预训练权重文件随仓库离线放在 `oresorter/ml/weights/`（`resnet18-f37072fd.pth`、`mobilenet_v3_large-8738ca79.pth`，来自 torchvision 发布），运行时不下载。

### 6.2 一键训练配方（固定，不暴露超参给操作工）
- 数据：当前模型目录下所选类别的全部有效样本（排除软删除）；每类 < `min_samples_per_class`（默认 20）拒绝训练并返回原因；分层划分 80/20 作验证集（可选 5 折交叉验证模式用于评估报告）。
- 采样：类别均衡采样（WeightedRandomSampler）。
- 增广：水平/垂直翻转、随机 90° 旋转、随机缩放 0.8~1.2、亮度/对比度 ±10%。
- 优化：AdamW；先 3 个 epoch 只训分类头（lr 1e-3），再全网微调（lr 1e-4，cosine 衰减）；label smoothing 0.05；batch 32；AMP FP16；最多 30 epoch，验证 macro-F1 连续 5 轮不升则早停；总时长上限 `max_train_minutes`（默认 10）。
- 输出：`best.pt`、`model.onnx`（动态 batch，opset 17）、`metrics.json`（验证准确率、macro-F1、混淆矩阵、每类 P/R/F1/support、训练曲线）、`train.log`、`meta.json` 更新（类别顺序、image_size、算法、时间、样本数）。
- 预期耗时：1000 张样本、160 px、ResNet18，在 Orin Nano 8G 上约 2~4 分钟。

### 6.3 部署
- `deploy(model_id)`：若无引擎或引擎与当前 TensorRT 版本不匹配，用 `trtexec --onnx --fp16 --minShapes=input:1x3xSxS --optShapes=input:32x3xSxS --maxShapes=input:128x3xSxS` 生成 `model.plan`（约 30~90 s），然后原子切换推理器；生成失败则回退 PyTorch FP16 推理并上报 warning。
- 一致性测试：同一批小图 PyTorch 与 TensorRT 输出 top-1 一致、概率误差 < 1e-2。
- 自动重新部署：训练完成时，若该模型是当前方案则自动部署（原始需求要求），切换瞬间最多影响 1 个块。

### 6.4 GPU 共享
- 训练子进程 `nice 10`，batch 32，AMP；分选运行中允许训练，但 HMI 应提示吞吐可能下降；推理延迟超过阈值时记录 warning。
- 显存预算：推理引擎 ≈ 200 MB，训练 ≈ 2~3 GB，相机缓冲 ≈ 100 MB，总 8 GB 共享内存足够。

## 7. 可靠性设计（工业级）

### 7.1 HMI 链路（HTTP + WebSocket）
- 后端是**状态唯一来源**；HMI 启动/重连后调用 `GET /state` 全量同步，不在前端缓存业务状态。
- 所有写操作同步返回结果（生效值、下位机确认情况、警告）；参数先校验、再持久化、再下发下位机；下位机未确认时返回 `mcu_ack=false` 并在 WS 推送最终结果。
- 写操作可带 `request_id` 幂等（60 s 内重复提交直接返回首次结果），防止网络重试导致重复执行。
- WebSocket：服务端每 5 s ping，客户端 pong；前端断线自动重连；预览帧限频（默认 ≤ 10 fps，JPEG 质量可调），发送队列满时丢旧帧而不是堆积。
- 接口带版本前缀 `/api/v1`；OpenAPI 文档由 CI 导出到 `docs/openapi.json`，前端按此联调。
- 不做鉴权（内网专用），但只监听配置的网口 IP。

### 7.2 下位机链路（TCP）
- 长连接，`TCP_NODELAY`，内核 keepalive；应用层心跳 200 ms；1 s 无心跳回复 → 链路故障 → `fault` 状态并告警；下位机侧 1 s 无心跳 → 自行停阀（安全态，需固件实现）。
- 每帧带序列号与 CRC16；控制/参数类指令必须 ACK，超时 200 ms 重发，3 次失败置故障；EJECT 流不等 ACK，但下位机每秒上报收到/执行/丢弃计数用于对账。
- 断线指数退避重连（0.5 s → 5 s），重连成功后重新下发全部参数并 `SYNC`。
- 协议编解码与状态机在无网络情况下用 Mock 下位机全覆盖测试。

### 7.3 相机链路
- SDK 异常、超时、丢块全部计数并上报；掉线自动重连（退避），重连后恢复参数并重新开始流；连续 N 次失败置 fault。
- 采集线程最高优先级；处理线程落后时环形队列丢最旧块并计数（不允许无限堆积）。

### 7.4 系统级
- systemd `Restart=always` + `WatchdogSec`（sd_notify）；开机自启；日志 journald（可选落盘轮转）。
- 配置/元数据原子写；模型部署原子切换；磁盘剩余空间 < 阈值时拒绝采样并告警；样本数/模型目录大小有上限。
- 所有后台任务有超时与取消；主循环异常不致命（捕获、计数、告警），崩溃由 systemd 拉起。
- 48 小时连续运行无内存增长（验收项）。

## 10. 运行环境与依赖

- JetPack 6.x 自带 CUDA、cuDNN、TensorRT、`python3-libnvinfer`；`trtexec` 在 `/usr/src/tensorrt/bin/`。
- PyTorch / torchvision：必须用 NVIDIA 为 JetPack 编译的 wheel（`https://developer.download.nvidia.com/compute/redist/jp/`，按 JetPack 小版本选目录；或 Jetson AI Lab 的 pip 索引），torchvision 版本须与 torch 匹配；下载后放入内网制品库，`requirements-jetson.txt` 指向本地 wheel。
- 海康 MVS SDK：`MVS_STD_GML_V2.x_aarch64.deb`（海康机器人官网），安装到 `/opt/MVS`；Python 封装 `MvImport` 以 vendor 方式复制进 `oresorter/camera/hik_sdk/` 或通过 `PYTHONPATH` 引入。
- 其余：numpy、opencv-python-headless、fastapi、uvicorn[standard]、pydantic v2、pyyaml、pillow、onnx、scikit-learn（仅评估指标）、pytest、httpx。
- 开发机（Mac/PC）：同一份代码，不装 MVS SDK 与 TensorRT，自动降级为 Mock 相机 + PyTorch 推理。
