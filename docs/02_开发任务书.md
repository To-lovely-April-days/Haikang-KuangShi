## 1. 阶段划分

| 阶段 | 目标 | 交付 | 验收 |
|---|---|---|---|
| **P0 工程骨架**（半天） | 仓库可运行、可测试 | 目录结构、配置模型与持久化、日志、CLI、pytest、Mock 相机/下位机 | `pytest -q` 全绿；`cli serve` 在 Mac 上起得来，`GET /api/v1/state` 有返回 |
| **P1 识别率验证工具链**（核心） | 无硬件也能完成"采集→切图→标定→训练→评估"闭环 | camera（Hik 封装 + Mock）、vision（分割、拼接、预处理、喷头映射）、data/store（样本库全部操作）、ml（训练、指标、ONNX 导出、PyTorch 推理）、`cli eval` / `cli replay` | 用合成数据与真实样本目录跑通；`cli eval --folder` 输出交叉验证混淆矩阵；喷头映射 64 行表全过；训练→ONNX 推理一致 |
| **P2 服务化** | HMI 可对接、运行时流水线可跑 | api（docs/03 全部接口 + WS）、runtime（状态机、流水线、任务系统）、mcu（协议、TCP 链路、Mock）、systemd 单元、OpenAPI 导出 | 接口清单逐条有集成测试；Mock 相机 + Mock 下位机下跑 1 小时无丢块、无内存增长；协议编解码测试全过 |
| **P3 Jetson 联调** | 真机 | Hik 真相机、TensorRT 引擎、网络与系统调优脚本、性能报告、48 h 老化 | §4 性能指标达标 |

P1 是当前优先级，P2 其次。P3 需要硬件，由项目负责人在 Jetson 上执行，Claude Code 提供脚本与检查清单。

## 3. 模块职责与接口

### 3.1 config
- `AppConfig`（pydantic）按 docs/01 §9 分组；每个字段带范围校验；`load(path)`、`save_atomic()`；运行时修改通过 `ConfigService.update(section, patch) -> (applied, warnings)`，校验失败抛 `ConfigError(code, message, detail)`。
- 测试：越界拒绝、原子写（写入中断不损坏旧文件）。

### 3.2 camera
```python
@dataclass
class Frame:
    seq: int            # 块序号（自 start_stream 起）
    line_start: int     # 该块首行的全局行号（自 SYNC 起）
    image: np.ndarray   # (h, w, 3) uint8 RGB
    ts: float           # 单调时钟

class Camera(ABC):
    def open(self) -> None; def close(self) -> None
    def get_params(self) -> CameraParams; def set_params(self, p: CameraParams) -> CameraParams
    def awb_once(self) -> None
    def snapshot(self, height: int) -> np.ndarray
    def start_stream(self, chunk_lines: int) -> None; def stop_stream(self) -> None
    def frames(self, timeout: float) -> Iterator[Frame]
    def reset_line_counter(self) -> None
    @property
    def connected(self) -> bool
```
- `MockCamera`：从目录循环读取大图（或 `make_synthetic.py` 生成），按 `chunk_lines` 切块，模拟行频节奏（可加速）；可注入丢块/断线。
- `HikCamera`：枚举/按 IP 或序列号打开；设置 `PixelFormat=RGB8Packed`、`Width/OffsetX/Height`、`ExposureTime`、`BalanceWhiteAuto`、`AcquisitionLineRateEnable/AcquisitionLineRate`、`TriggerMode/TriggerSource`（行触发时按海康线阵的编码器/分频模块设置，节点名以 MVS 客户端实测为准）；`GevSCPSPacketSize` 取最优值；回调或拉取模式取帧转 numpy；丢块按 `nFrameNum` 断号补偿 `line_start`。无 SDK 时导入失败要给出清晰错误，不影响 Mock 路径。**状态**：已按 SDK 公开 API 预实现（`oresorter/camera/hik.py`，假 SDK 单测 `tests/test_camera_hik.py` 覆盖枚举/参数/取流/断号/重连/关闭），节点名待真机核对，核对清单见 `deploy/jetson_checklist.md`。

### 3.3 vision
- `background.ColumnBackground.learn(frames) / distance(image) -> float32 map / save / load / adapt(image, fg_mask, rate) -> 更新列数`（只更新本帧无前景的列，EMA）；`ColorBackground(bg_color)`（`color` 模式）只提供 `ready / width / lab / distance / row_rgb`，**没有** `learn / save / load / adapt`，因此 `capture.bg_adapt_rate` 在 `color` 模式下无效；`make_background(settings, column_bg)` 按 `bg_mode` 选背景（column 未学习抛 ValueError "请先学习背景"）；`background_path(data_dir, camera_id)` → `background/cam{id}.npz`；`learn_bg_cli(args)` 是 `cli learn-bg` 的实现（从相机快照或图片目录学习并保存）。
- `segment.segment(image, bg, settings) -> list[Particle]`（按 `trailing_y` 升序，同行按 x）；`Particle(bbox, centroid_x, centroid_y, area, trailing_y, crop_rgba, touches_top, touches_bottom, truncated, trailing_line, extra)` 是 vision / runtime / data / api 共用契约，**字段只增不删**；另有 `foreground_mask(image, bg, settings) -> uint8 mask`（预览 / 自适应用）、`draw_overlay(image, particles) -> RGB`（画框与编号，`/capture/preview` 与 snapshot overlay 用）、`particle_stats(particles)`、`resolve_background(bg, settings)`、`split_touching_mask(roi_mask, *, max_area=None)`（`max_area` 仅关键字）。
- `stitch.ChunkStitcher(overlap, *, max_object_lines=None)`：`push(frame) -> (image, y_offset)`、`select(particles, image_h) -> list[Particle]`（docs/01 §5.2 规则，填 `trailing_line` 与 `extra["seq"/"y_offset"]`，按 `trailing_line` 升序）、`process(frame, segment_fn)` 一步到位；`last_chunk` / `last_frame` 返回 `ChunkInfo(seq, line_start, lines, width, ts, camera_id)`（**不含 image**，拼接器只缓存尾部拷贝）；`stats()` 含 `frames / dropped / resets / deferred / skipped_seen / truncated / selected / lost`；`reset()`。
- `preprocess.to_tensor(crop_rgba, image_size) -> np.ndarray(C,H,W)`、`to_tensor_batch(crops, image_size) -> (N,3,S,S) float32`，训练与推理唯一入口；`mask_from_background` 为无 alpha 图片抠 mask（与 `bg_threshold` 同一 Lab 约定）。
- `nozzle.NozzleMap(start_px, end_px, n=64, *, camera_index=0)` / `NozzleMap.from_camera(cfg, camera_index)`：`ranges()`、`widths()`、`pixel_to_nozzle(x)`、`span(x0, x1, expand=0)`（`x0 > x1` 自动交换）、`global_span`、`to_global`、`to_dict()`；x 为传感器坐标（图像列号 + `offset_x`）；`test_nozzle.py` 用 `docs/00_原始需求` 中规则生成 r=0..63 的期望表逐行比对。
- `replay.run(args)`（`cli replay --images DIR [--config YAML] [--model-dir D] [--chunk-lines N] [--out DIR] [--learn-bg N]`）：回放大图目录走 分割 →（有模型时）分类，输出标注图与 `replay_report.json`。
  - 两种方式：**整图**（默认，每张图独立 `segment.segment`，顶到上下边的颗粒按完整计数、条目带 `touches_top / touches_bottom`，`totals.edge` 给边界颗粒数）；**按块** `--chunk-lines N`（128~4096，越界拒绝）把每张图按 N 行切成 `Frame` 经 `ChunkStitcher(cfg.pipeline.overlap_lines)` push / select，与运行时流水线同一路径，每张图末尾再推一帧纯背景**冲洗帧**让被延后的触底颗粒得到处理，因此 `stitch.frames = 块数 + 1`；块内坐标换算回大图坐标，两种方式结果可直接比较；`overlap_lines=0` 时跨块颗粒会被切成两半且不标记截断，给 warning。
  - 背景：`--learn-bg N > 0` 用前 N 张图学 `ColumnBackground`（**N 大于图片数按越界拒绝**），否则 `ColorBackground(cfg.capture.bg_color)`（配置为 column 但未给 `--learn-bg` 时记日志改用颜色背景）；报告 `config.bg_info = {frames_used, width, mean_rgb}`。
  - 输入 / 输出：`--out` 默认为图片目录同级的 `replay_out/`，**不得是图片目录本身或其子目录**（否则标注图会被下一次回放当作输入）；输入目录中以 `_overlay.jpg` 结尾的文件视为上次产物跳过并告警；标注图 `{stem}_overlay.jpg`，同名不同扩展名的图片（`a.png` / `a.jpg`）改用 `{stem}_{ext}_overlay.jpg`（仍重复再加序号）以免互相覆盖。
  - `replay_report.json`（`version: 2`）：`created_at / images_dir / out_dir / elapsed_s`、`config{path, capture, overlap_lines, chunk_lines, mode: whole|chunked, bg, bg_info, learn_bg, model_dir, backend, classes, image_size}`、`totals{images, images_ok, images_failed, particles, per_class, area_mean, truncated, edge, labels}`、`timing_ms{p50, p99, mean, max, total}`、`images[]`（每张 `name / width / height / count / per_class / area_mean|min|max / truncated / edge / segment_ms / infer_ms / ms / overlay / stitch / labels / particles[]`，失败的图为 `{name, error, error_type}`）。目录含 `labels.json`（`synthetic.make_frames` 产物）时按 IoU ≥ 0.5 一对一贪心匹配给出 `n_labels / n_detections / matched / recall / false_positives`，有模型时再给匹配颗粒上的 `cls_evaluated / cls_correct / cls_accuracy`；`labels.json` 中缺键或值不是列表的图片不参与统计并告警，`totals.labels.images_without_labels` 计数。
  - 返回码：0 成功；1 = 参数 / 环境错误（目录不存在、`chunk_lines` 越界、`learn_bg` 越界、模型目录无产物、配置加载失败、输出目录落在图片目录内）或有单张图回放失败（单张失败只记 error 条目，其余继续，报告照常写出）。

### 3.4 data
- `ModelStore(root, max_models, class_names, *, thumb_size=160, min_free_mb=0)`：`ensure_root()`、`create(id, name, description)`（已存在 CONFLICT）、`delete(id, deployed_id)`（`id == deployed_id` → CONFLICT）、`backup(src, dst, overwrite)`（锁外整目录复制 + `atomic_replace_dir`，复制后改写 meta.id 与 journal 前缀；目标已存在且未 overwrite → CONFLICT）、`list(deployed_id)`（未创建编号返回占位项，损坏的 meta.json 降级为默认值）、`describe(id, deployed_id)`、`created_ids()`、`meta(id) -> ModelMeta`、`update_meta(id, **patch)`、`samples(id) -> SampleRepo`（缓存实例，**SampleRepo 一律经此获取**）、`exists / trained / has_onnx / has_engine(id)`、`disk_usage(id)`、`rename_class(old, new)`（全部已创建模型的目录 + journal + meta 一起迁移，供 `PUT /config/classes` 改名用）、`set_class_names(names)`。
- `SampleRepo(model_dir, class_names, *, thumb_size=160, min_free_mb=0)`：`add(cls, crop_rgba, meta) -> Sample`（`min_free_mb` 不足拒绝；cls 必须在 `class_names` 内）、`list(cls, include_deleted, offset, limit) -> (total, [Sample])`（**按 seq 升序**，最早写入在前，排序键取自文件名无需读 json）、`get(sample_id)`、`count / counts / iter_active`、`soft_delete(ids) -> batch | None`（一次只允许同一类别、ids 去重，全部已删除返回 None）、`restore(sid) -> bool`、`undo_last(cls) -> int`（撤销最近一次删除批次，批次栈持久化到 `samples/.trash/journal.json`；无批次抛 NOT_FOUND）、`clear(cls) -> (n, batch | None)`（整类软删除为一个批次）、`purge(older_than_s)`、`rename_class(old, new)`、`refresh_seq()`（目录被外部整体替换后重扫 seq）、`orphan_classes()`（磁盘上存在但不在 `class_names` 的历史类别）、缩略图生成；文件名 `cam{id}_{YYYYmmdd_HHMMSS}_{seq:06d}`，`seq` 为仓库级单调计数（与时间戳同一临界区取得，并发唯一）；写入原子。
  - 样本 json 只存 `camera_id / bbox / area_px / created_at / seq / batch / extra`，**不含 sample_id / cls**（由路径推导，备份至 / 类别改名后无需重写）；`Sample.to_dict()` 的 `thumb_url / image_url` 按实际位置生成，已软删除的样本带 `.trash/` 段。
  - `StoreError(code, message, detail)`，`code ∈ VALIDATION / NOT_FOUND / CONFLICT / INTERNAL`（文件系统错误统一 INTERNAL）。

### 3.5 ml
- `Classifier` 接口：`load(model_dir)`、`predict(batch) -> (probs, classes)`、`predict_top`、`warmup()`、`close()`，属性 `classes / image_size / backend`；实现 `TrtClassifier`（TensorRT 不可用抛 `ClassifierUnavailable`；加载时核对引擎输入尺寸与**输出类别维 == len(classes)**，不一致拒绝加载，避免越界写显存）、`OnnxClassifier`、`TorchClassifier`；`load_classifier(model_dir, prefer=("trt","onnx","torch"), device="auto", *, max_batch, opt_batch)` 按顺序降级；`read_model_meta(model_dir)` 优先读 `train/best.pt` 内的 meta（mmap，不读整份权重），缺项再用 `meta.json` 补，两处都没有 classes / image_size 抛 `ClassifierUnavailable`；`compare_outputs(a, b) -> {top1_agree_rate, max_abs_diff, n}`。
- `train.run(model_dir, classes, cfg, *, class_names, progress_cb, stop_event)`：按 docs/01 §6.2 配方；`TrainConfig.from_ml_config(ml, strict_image_size=…, **overrides)`；子进程入口 `python -m oresorter.ml.train --model-dir D --config YAML [--classes A,B] [--nice 10]`（任务层以 `--nice 10` 启动；`--image-size` 严格限 128/160/224）。文件约定：
  - `train/progress.json` 每次进度原子覆盖：`{progress, stage, status ∈ prepare|running|done|cancelled|failed, epoch, epochs, elapsed_s, best_epoch, classes, [val_macro_f1, val_accuracy, artifacts, error]}`，主进程轮询并转发 WS `job` 事件；
  - 失败/取消时另写 `train/error.json {code, message, detail, ts}`，退出码 1，同一 JSON 也输出到 stderr（模型目录不存在时不落盘）；`code ∈ NOT_FOUND / VALIDATION（detail.insufficient 为样本不足的类别）/ CANCELLED / INTERNAL`；
  - 取消语义：父进程 `terminate()`（SIGTERM/SIGINT）→ 子进程置 stop_event 优雅停止 → 退出码 1、`error.json code=CANCELLED`、progress `status=cancelled`，**已写的 best.pt 保留**。
- `train.cross_validate(items, classes, cfg, k=5, progress_cb=None, *, loo_threshold=50, stop_event=None)`：样本数 < 50 改留一法（k = n）；每折跑满 `max_epochs` 不按验证折选 best（避免泄漏），总时长预算按折平分。
- `metrics.report(y_true, y_pred, classes) -> dict`（混淆矩阵、每类 P/R/F1/support、准确率、macro-F1）、`metrics.summary(report)`、`format_report(report)`。
- `export.to_onnx(model, image_size, path)`（动态 batch，校验输入形状）、`export.build_engine(onnx, plan, image_size, *, fp16, timeout_s, trtexec, max_batch, opt_batch)`（调用 trtexec，默认超时 10 min，产物原子写；引擎旁写模型元信息 `model.json {trt_version, onnx_sha256, image_size, plan_bytes, …}`）、`engine_matches(plan, onnx, *, trtexec, image_size) -> bool`（文件齐全 + ONNX sha256 一致 + TensorRT 版本一致，任一信息缺失按不匹配）、`find_trtexec()`、`EngineBuildError`；`cli build-engine --model-dir D [--no-fp16] [--timeout] [--trtexec] [--max-batch] [--opt-batch]`。
- `cli eval --folder DIR`（`ml/evaluate.py`）：DIR 下每个子目录是一类（直接支持客户现有的 a/ b/ c/ 目录，图片可为 bmp/png/jpg，无 alpha 时用 `--bg-color`（默认蓝底）自动抠 mask）；做 `--folds`（默认 5；样本少于 50 自动改留一法）交叉验证，打印混淆矩阵与每类指标，并保存 `eval_report.json`；`--image-size / --epochs / --folds` 越界直接报错，不静默回退（`--image-size` 仅用于评估，**当前实现**接受 ≥ 8——与 docs/01 §9 不一致，是否收紧待拍板（docs/01 §11 #9）；训练子进程严格限 128/160/224）。

### 3.6 mcu
- `protocol.py`：帧结构、`encode(cmd, payload=b"", *, seq, addr=0x01, ver=0x01)`（`seq` 仅关键字，按位置传会 TypeError）、`encode_ack(req, result, data)`、`decode(buf) -> frames`、`FrameParser(max_buffer, *, check_header=True)`（流式，处理粘包/半包；`check_header` 对 SOF 后的 VER / ADDR / CMD 做头部预检——`VER≠0x01`、`ADDR∉{0x01,0xFF}`、`CMD=0x00` 或 `LEN>1024` 立刻视为失步，丢弃该 SOF 从下一个 SOF 重同步，不等 LEN 字节到齐；计数 `frames_ok / crc_errors / header_errors / resyncs / bytes_dropped`）、CRC16-MODBUS、`Cmd / Report / AckResult / McuState / ParamId / EventCode` 常量、负载打包（`pack_heartbeat / pack_sync / pack_set_param / pack_eject / …`，`StatusPayload`（19 B）/ `EventPayload` / `CountersPayload`）、`params_from_config(cfg)` / `params_for_section(cfg, section)` → `{ParamId: int}`、`check_param_range`。
- `McuLink` 接口：`connect / close / connected / status -> McuStatus(to_dict)`、`send(cmd, payload, *, need_ack=True, timeout=None) -> Ack`（None = 用 `ack_timeout`）、`send_eject([EjectItem(line, nozzle_first, nozzle_last, flags)])`、`on_event(cb(LinkEvent(kind, data, ts))) -> unsubscribe`（`kind ∈ connected | disconnected | status | event | counters | fault | nack`；fault 事件有两种形态：链路故障 `{code: "MCU_HEARTBEAT_TIMEOUT" | "MCU_ACK_TIMEOUT", …}`，与设备故障位 `{code: int, active: bool}`（STATUS 位图 bit n，`AppContext` 映射为顶层故障 `MCU_FAULT_{code:04X}`；**目前只有 `MockMcuLink.inject_fault` 发**，`TcpMcuLink` 收到位图变化不发该事件、只写入 `status.faults` 文字，两种链路下 HMI 顶层 `faults` 不一致，待统一，见 docs/03 §3）；event 的 `data` 含 `code / level / detail / text`，`level == 2` 为故障）及便捷方法 `heartbeat / sync / run / pause / stop / set_params / get_params / push_all_params / valve_test_single / valve_test_cycle / valve_test_stop / valve_reset / clean_now / reset_link`；异常 `McuNack(result, cmd) / McuTimeout / McuDisconnected`。
- `TcpMcuLink`：三个 daemon 线程（连接管理 / 读取 / 心跳，`close()` 2 s 内 join）。**心跳语义**：每 200 ms 发 HEARTBEAT，不等 ACK、不重发、不计入 `ack_timeouts`；任何 CRC 正确的 STATUS(0x81) 帧（含只有 result 字节的 NACK）刷新看门狗，只有带完整 StatusPayload 的帧更新状态快照与 RTT（负载 ≥ 20 B 按 `result + StatusPayload` 解析；恰为 19 B 的裸 StatusPayload 视为主动上报、result=0 也接受；1 B 为 NACK，见 docs/04 §6）；> 1 s 无 STATUS → `fault(MCU_HEARTBEAT_TIMEOUT)` 并断开重连；心跳被 NACK 时保持连接，`status.faults` 含"心跳被拒绝"。ACK 按 SEQ 匹配，超时重发同一 SEQ 3 次后 `fault(MCU_ACK_TIMEOUT)` 并断开；重连退避与"不稳定连接"规则见 docs/01 §7.2；连上后 `push_all_params()` + `reset_link()`（不发 SYNC）。
- `MockMcuLink(cfg)`：进程内 Mock（`McuModel` 状态机、编码器计数、喷阀队列、参数表）；注入：`set_offline(bool)`、`inject_ack_timeouts(n)`、`inject_nack(result)`、`inject_fault(code, active)`（置 STATUS faults 位图 `bit = code`）；观察：`model.fired`、`model.params`、`debug_state()`。
- `MockMcuServer(host, port)`：实现协议另一端的 TCP server（线程），按 SEQ 缓存 ACK（重复 SEQ 幂等只重发 ACK，不重复执行），HEARTBEAT 的应答即 STATUS(0x81)，每 1 s 推 COUNTERS；故障注入：`drop_acks(n)`（**不作用于 HEARTBEAT**，否则后台心跳会不确定地消耗计数、测试无法断言重发次数；心跳丢失请用 `silent`）、`silent`（不回应但指令仍执行，COUNTERS 暂停）、`ack_delay_s`、`corrupt_next_ack()`、`disconnect_clients()`、`send_event(code, level, detail)`、`heartbeat_result`（≠0 时 HEARTBEAT 只回 1 字节 result 的 NACK，不带 StatusPayload，用于测心跳看门狗对 NACK 的容忍）。

### 3.7 runtime
- `context.AppContext(config: ConfigService)`：组合根——`cfg / data_dir`、`state_store`（`state.json`：`deployed_model_id / uptime_total_s / bg_version / last_run_state`，`update(**patch)` 原子写）、`faults`（`FaultRegistry.set / clear / active / has / codes / subscribe(cb(code, active, detail))`）、`cameras{id: Camera}`、`mcu`、`start() / stop()`（单个设备失败只记故障不抛）、`uptime_total_s() / flush_uptime()`、`snapshot()`（`GET /state`，`version` 为包版本 `oresorter.__version__`，不读 `system.version`）。
- `state.StateMachine(initial, on_change)`：docs/01 §4.3；`transition(event) -> RunState`，非法抛 `IllegalTransition`（code CONFLICT，`detail.reasons` 用常量 `NO_MODEL_DEPLOYED / CAMERA_DISCONNECTED / MCU_DISCONNECTED / SAMPLING_IN_PROGRESS / IN_FAULT / ALREADY_RUNNING / NOT_RUNNING / NOT_SAMPLING`）；幂等事件（含 `fault+stop`、`fault+fault_raised`）返回当前状态、不记历史、不触发监听；`can / subscribe / history / previous / to_dict`；`check_start_preconditions(*, deployed_model_id, cameras_connected, mcu_connected) -> [reasons]`。faults 集合（code、since、detail）在 `AppContext.faults`。
- `events.EventBus(history=200)`：进程内**同步**事件总线 `publish(type, data) -> event`（生成 `{"type", "ts", "data"}`，回调在锁外执行、异常被捕获）/ `subscribe(cb) -> unsubscribe` / `recent(n, type)`（环形缓冲）/ `published_total`；`state / stats / job / capture_sample / param_sync / fault / mcu` 事件统一经此进入 `ws.py` 广播（docs/03 §11），未知类型只记 warning。
- `service.RuntimeService(ctx)`：门面，把 API 路由与状态机、设备、任务、统计解耦；全部方法线程安全（运行控制串行在 `lock`（RLock）下，`AppContext.set_classifier` 也用它与建流水线互斥），返回的 dict 即 docs/03 响应体。方法名与接口一一对应：`snapshot / run_stats`；`start / pause / stop`（`start` 的 stopped → running：前置检查 + `_require_backgrounds` 背景预检 → 取消喷阀循环检测任务 → `stats.reset()` → `mcu.sync(clear_encoder=True)` + 全部相机 `reset_line_counter()` → 每相机一条 sort `Pipeline` → `mcu.run()`；paused → running 只 `mcu.run()` + `set_blow_enabled(True)`，不 SYNC；`stop` 在 sampling 态先锁外取消采集任务再 STOP、停流水线，`fault` 态仍转发 STOP）；`get_params / update_params`（`MCU_SECTIONS` 经 `params_for_section` 推到下位机，`mcu_ack` 三态，NACK 回滚；capture / blow 热更新流水线）；`valve_test_single / valve_test_cycle / valve_test_stop / valve_reset`（running / paused / sampling → 409）；`list_cameras / camera_params / update_camera_params / awb_once / nozzle_map / snapshot_image / capture_preview / acquire_preview`（预览句柄 `PreviewHandle.get_frame(timeout) / release()`，引用计数：流水线在跑复用其帧，否则按需开流、最后一个持有者释放时停流）；`list_models / current_model / create_model / patch_model / delete_model / backup_model / deploy_model(model_id, *, exclude_job_id=None) / model_metrics / train_model`（同一模型 deploy ↔ train ↔ backup 目标互斥）；`get_classes / set_classes`；`start_capture / list_samples / delete_sample / delete_samples / restore_sample / undo_delete / clear_samples`；`get_job / list_jobs / cancel_job`；`save / shutdown(reboot=False)`。采样生命周期 `begin_capture(pipeline) / end_capture(pipeline)` 由 `capture_task` 调用（来源 paused 时挂起 / 恢复分选流水线）；故障反应 `on_fault_raised(code)` 由 `AppContext` 调用（另起线程复查仍为 fault 后取消采样 / 喷阀检测任务、尽力 STOP、停流水线）；`quiesce()` 供 `AppContext.stop`。
- `tasks.py`：五类任务函数工厂，返回 `fn(handle: JobHandle) -> dict`——`capture_task(ctx, model_id, cls, camera_id, max_samples, max_frames, timeout_s)`（建 capture `Pipeline` + `CaptureSink`，`begin_capture` → 运行分割并写入 `SampleRepo`，每写一张推送 `capture_sample`，张数 / 帧数 / 时长上限、取消或流水线停止时结束，`end_capture` 恢复状态；结果 `{count, frames, stop_reason, error}`）、`train_task(ctx, model_id, classes)`（先清理 7 天前回收站样本，`write_runtime_config` 把生效配置写成 `{data_dir}/runtime_config.yaml`，启动 `python -m oresorter.ml.train --model-dir D --config runtime_config.yaml --nice 10 [--classes]` 子进程（输出到 `train/subprocess.log`），每 0.5 s 轮询 `progress.json` 转进度，取消 = SIGTERM、10 s 不退 SIGKILL；失败 `message` 取 `error.json.message`；成功 `result` 以 docs/03 §10 为契约：`metrics_summary / artifacts{onnx, engine: false} / classes / epochs / duration_s`，若为当前部署模型则自动提交 deploy（`exclude_job_id=自己`）并附 `redeploy_job_id`，提交失败附 `redeploy_error`）、`deploy_task(ctx, model_id)`（`engine_matches` 判断是否重建引擎 → `load_classifier` → 预热 → 与 PyTorch 一致性自检（top-1 不一致回退 PyTorch 并 warning）→ `ctx.set_classifier` 原子切换并写 `state.deployed_model_id`；结果 `{model_id, backend, engine, consistency, image_size, classes, warnings}`）、`backup_task(ctx, src, dst, overwrite)`（`ModelStore.backup`；结果 `{target_id, source_id, name}`）、`valve_test_cycle_task(ctx, frm, to, interval_ms)`（下发 VALVE_TEST_CYCLE，等待取消，收尾 VALVE_TEST_STOP；结果 `{stopped: true}`）。
- `pipeline.Pipeline(ctx, camera, *, mode="sort"|"capture", sink=None, camera_index=None)`：三线程（acquire / process / send，capture 模式无 send）+ 环形队列（`pipeline.queue_size`，满丢最旧并计数）；`start(*, reset_lines=False)`（**缺省不重置行号**，SYNC + 行号归零只在 `RuntimeService.start()` 一处；背景缺失抛 `BackgroundUnavailable`，开流失败置 `CAMERA_{id}_DISCONNECTED` 并抛 `CameraStreamError`）、`stop(timeout=2) -> bool`、`process_frame(frame) -> ChunkResult`（不起线程的同步路径：push → segment → sink → 统计，测试与 `cli replay` 复用；只有 sort 模式写 `ctx.stats`）、`healthy()`（喂狗判定：线程都活着且没有"收到块却长时间不处理"，相机静默 / 断线不算；`cli serve` 的 `_healthy` 遍历 `ctx.pipelines` 全部流水线）、`stats()`（拼接器统计 + 队列 / 处理 / 发送计数，docs/03 §3 `pipeline`）、热更新 `replace_classifier(clf, *, close_old=False) / set_blow_enabled / update_blow / update_capture_settings / update_nozzle_map`、预览 `latest_frame / wait_frame(after, timeout) / collect_lines(lines, timeout)`（运行中快照拼连续块）。故障：`frame_timeout_s` 内无块 → `CAMERA_{id}_TIMEOUT`（本流水线再收到帧时清除；流水线已停且相机在线时由 `AppContext._poll_devices` 清除；`RuntimeService.stop()` 也清除 TIMEOUT 与 `PIPELINE_ERROR`）；掉线 → `CAMERA_{id}_DISCONNECTED`，等相机恢复后重新开流并复位拼接器；处理线程连续 20 次异常 → `PIPELINE_ERROR`；`ClassifySink` 连续 20 块推理失败 → `CLASSIFIER_ERROR`（替换分类器清零）；`latency_warn_ms` 超限告警（同类告警 5 s 一条）。两种 `ParticleSink`：`ClassifySink`（预处理 → 分批推理 → `decide_batch` → `eject_items_counted`，暂停时只分类不吹）、`CaptureSink`（写 `SampleRepo`，跳过截断颗粒，达到上限置 `done`）。
- `decision.decide(particle, probs, classes, blow, *, max_area_px, blow_truncated=False) -> Decision(blow, cls, conf, reason)` / `decide_batch` / `eject_items_counted(particles, decisions, nozzle_map, *, offset_x, expand=0) -> (items, skipped)`；规则见 docs/01 §4.2，`size_norm(area, max_area_px)`、`confidence_threshold(blow)` 可单测。
- `jobs.JobManager(on_event, max_history=200, progress_event_min_interval=0.1)`：`submit(type, fn, *, model_id, exclusive=True, meta) -> Job`（同类型已有 queued/running 任务抛 `JobConflict`，409）、`get / list / active_list / running(type)`、`cancel(id) -> bool`（queued 直接 cancelled 不执行 fn；running 置取消事件由任务函数自行结束）、`wait(id, timeout=30)`（默认 30 s，不提供无限等待）、`shutdown(timeout)`；`JobType ∈ capture | train | deploy | valve_test | backup`；`JobHandle(job_id, job, cancelled, check_cancel(), set_progress(p, stage), cancel_event, log)`。
  - 取消语义：任务函数正常返回但取消已请求 → `status=cancelled` 且 **`result` 保留**；抛 `JobCancelled`（或取消已请求时抛任何异常）→ cancelled；其他异常 → failed，`message=str(exc)`；只有 succeeded 才把 `progress` 置 1。
  - 进度事件限频：同一任务两次进度事件间隔 ≥ 0.1 s，`stage` 变化与结束事件不限频；被压下的最后一次进度在间隔到期后由 daemon 定时器补发（任务结束时在结束事件之前补发）。`job.to_dict()` 字段 = docs/03 `GET /jobs/{id}` + `created_at`、`meta`。已结束任务按结束顺序保留最近 `max_history` 条。
- `stats.RunStats(*, window_s=60, latency_samples=2000, clock, class_names)`：`on_chunk(latency_ms, n_particles, blown, per_class, dropped)`、`on_dropped(n)`、`timer()`、`reset()`（每次 start 调用）、`snapshot()` → `particles_per_min / blown_per_min / per_class_per_min`（滑动窗口折算、四舍五入 int）、`chunk_latency_ms_p50 / p99 / max`（float）、`chunks_total / dropped_chunks / particles_total / blown_total / per_class_total`、`since / elapsed_s`；`per_class_*` 总含全部已配置类别（缺省 0，顺序同配置），未配置但出现过的类别追加在后。

### 3.8 api
- 与 docs/03 一一对应；`schemas.py` 的模型字段名就是接口字段名（请求体 `extra="forbid"`，响应体 `extra="allow"` 让 service 附带的补充字段透出）；错误统一为 `{"error": {"code","message","detail"}}`；路由只做转发，业务规则全部在 `RuntimeService`。静态文件 `/static -> data_dir` 用 `WhitelistStaticFiles` 只放行 `models/{id}/thumbs|samples/**`、`snapshots/*`、`previews/*`，其余 404。
- `app.create_app(ctx, manage_lifecycle=True)`：lifespan 调 `ctx.start()/stop()`（`startup_hooks / shutdown_hooks` 供 `cli serve` 挂 sd_notify），`app.state.ctx`、`app.state.idempotency`；`system.cors_origins` 非空时挂 `CORSMiddleware`（`allow_methods=*`、`allow_headers=*`、`expose_headers=[X-Idempotent-Replay]`）；按 `ROUTE_MODULES` 自动 include 各 `routes_*.router` 与 `ws.router`（前缀 `API_PREFIX=/api/v1`），模块有 `register(app, ctx)` 则调用；`errors.py` 把各模块异常映射为错误体：`ApiError`（service 自用，如 `DeviceOffline` → 503）按 code、`ConfigError / StoreError / TrainError`（CANCELLED → CONFLICT）按 code、`IllegalTransition / JobConflict / ClassifierUnavailable` → 409 CONFLICT、`McuNack` → 502 MCU_NACK、`McuTimeout` → 504 MCU_TIMEOUT、`McuDisconnected` → 503 DEVICE_OFFLINE、`RequestValidationError` → 400 VALIDATION、Starlette 404 → NOT_FOUND、未处理异常 → 500 INTERNAL。
- `idempotency.py`：`IdempotencyCache(ttl_s=60, *, max_entries=2000, clock)`（`get / put / run(key, fn) -> (value, replayed)`，同键并发合并等待先到者，单次等待上限 30 s，先到者抛异常则等待者自己执行）+ 纯 ASGI `IdempotencyMiddleware(app, cache, prefix="/api/v1")`：只拦截前缀下的 POST/PUT/PATCH/DELETE，读完整请求体取 `X-Request-Id` 头或 JSON 顶层 `request_id`（≤ 128 字符，头优先）作键 `(method, path, request_id)`，无键原样放行（请求体重放给下游）；命中回放首次 `(status, headers, body)` 并加 `X-Idempotent-Replay: 1`；未命中捕获下游完整响应后缓存（错误响应同样缓存）。选中间件而非依赖项：dependency 拿不到路由返回的响应。
- `ws.py`：`/ws/events`——先订阅 `EventBus` 再在线程池取快照，首条发 `state` 全量；后台线程的事件经 `loop.call_soon_threadsafe` 入每连接 `asyncio.Queue(200)`（满丢最旧）；发送阶段丢弃 `ts` 早于快照观察时刻的全量型事件（`state / stats / mcu`，`is_stale_snapshot_event`），增量型事件一律保留；每 5 s 发应用层 `{"type":"ping"}`，任何客户端消息刷新存活，15 s 静默以 1001 关闭；断开时取消订阅。`/ws/preview/{camera_id}`——`preview_options` 校验 `mode ∈ full|edges`、`fps` 1~`system.preview_max_fps`、`quality` 10~100、`max_width` 16~16384、`edge_px` 1~相机宽，越界 / 相机不存在发 `{"type":"error", code, message, detail, ts}` 后 1008 关闭（`detail` 即 `ConfigError.detail` 原样透出：`PARAM_OUT_OF_RANGE` 为 `{field,input,range}`，`mode` 非法的 `VALIDATION` 为 `{field,input}`，`NOT_FOUND` 为 `{camera_id}`）；`acquire_preview` 取句柄，线程池里 `_latest_frame`（跳过排队旧帧，只发最新）→ `encode_preview`（`full` 等比缩放到 `max_width`；`edges` 用 `compose_edges` 拼 `[0, edge)` + `[w−edge, w)` 两段、宽恒为 2×edge_px，`start_px / end_px` 减 `offset_x` 后在有效区首 / 末 2 列画白线）→ 文本帧头 + 二进制 JPEG，按 `fps` 限频；相机离线发 `DEVICE_OFFLINE` 后 1011 关闭；结束时在线程池里 `release()`（可能触发停流 join，不阻塞事件循环）。
- `scripts/export_openapi.py` 导出 `docs/openapi.json`，CI 检查与仓库中的一致。

## 4. 验收标准（P2/P3）

| 指标 | 目标 |
|---|---|
| 512 行块处理延迟（块到达 → EJECT 发出） | p50 < 40 ms，p99 < 80 ms（Jetson，含推理） |
| 持续吞吐 | 9 kHz 行频下 1 小时丢块 = 0（Mock 与真机各测） |
| 训练 | 1000 张样本、160 px、ResNet18 ≤ 5 min；指标报告完整 |
| 部署 | 含引擎生成 ≤ 120 s；PyTorch 与 TensorRT top-1 一致率 100%，概率差 < 1e-2 |
| API | 命令类接口 p99 < 100 ms（不含等待下位机 ACK 的时间） |
| 链路 | 下位机/相机断线后 ≤ 5 s 自动重连并恢复参数；HMI WS 断线重连后状态一致 |
| 稳定性 | Mock 下 48 h 连续运行，RSS 增长 < 50 MB，无线程泄漏（`scripts/soak_test.py --duration 48h` 退出码 0，见 §5） |
| 测试 | `pytest -q` 全绿；接口清单每条至少一个集成测试；喷头映射 64 行表全过 |

## 5. 测试计划

- **单元**：nozzle（64 行表）、protocol（编解码、CRC、粘包/半包、错误帧）、stitch（跨块颗粒恰好处理一次；触底对象延后；超长对象告警）、segment（合成图上数量/位置/面积误差）、preprocess（确定性、尺寸）、samples（软删除/撤销/清空/批次栈持久化/并发写）、config（范围、原子写）。
- **集成**：api（每个接口的正常与错误路径，TestClient + Mock 设备）、runtime（状态机全部迁移、采样任务、训练任务、自动重部署）、mcu_link（Mock server：心跳超时置故障、重连后全量重发参数 + RESET_LINK（不发 SYNC）、ACK 超时重发 3 次、不稳定连接退避翻倍）。
- **一致性**：train → onnx → infer；同一张图 PyTorch/ONNXRuntime/TensorRT 输出比对（TensorRT 部分仅在 Jetson 运行，用 `pytest -m jetson` 标记）。
- **老化**：`scripts/soak_test.py`（`tests/test_soak_script.py` 进程内调用 `main([...])` 覆盖）。
  - 参数：`--config`（默认 `config/dev.yaml`）、`--duration`（秒或 `30m / 1h / 48h / 2d`，默认 1h）、`--interval`（采样间隔秒，≥ 0.1 且 ≤ duration，默认 60）、`--out`（`.jsonl` 或 `.csv`，默认 `{data_dir}/logs/soak_YYYYmmdd_HHMMSS.jsonl`，给目录则在其中按默认名创建；已存在需 `--overwrite`）、`--model-dir`（已训练模型目录，省略则复用已部署模型，否则用合成样本快速训一个 128 px / 2 epoch 的临时模型，结束后删除并恢复原部署编号）、`--speed`（Mock 相机速度倍率 0~1000，0 = 不限速，默认 1.0）、`--rss-limit-mb`（RSS 相对基线允许增长，默认 50）、`--max-dropped`（可选，流水线 + 相机丢块上限）、`--log-level`。配置被强制为 `mcu_kind=mock`、相机 `kind=mock`、`auto_run_on_boot=false`，column 背景未学习时回退 color 模式；`blow.classes` 为空时临时设为模型全部类别、`min_confidence=0`（不落盘），让决策 → 喷头映射 → `send_eject` 链路被覆盖。
  - 退出码：`0` 合格；`2` 超限 = RSS 增长 > `--rss-limit-mb` / 线程泄漏 / 运行期间出现故障 / 结束时运行状态不是 running 或块数停止增长 / 给了 `--max-dropped` 且丢块超过；`1` = 参数非法、准备阶段（训练 / 导入 / 部署 / 启动）失败、运行开始前被中断或异常。运行期间任何故障或状态离开 running 由监听直接唤醒采样循环**立刻**结束；第一次 SIGINT / SIGTERM 优雅结束并出汇总，第二次强制退出（1）。启动与模型准备阶段的瞬时故障只记入 `startup_faults` / `notes`，不算运行期间故障。
  - 每行记录：墙钟时间、`elapsed_s`、`rss_mb`、Python / OS 线程数、CPU%、`run_state`、`ctx.stats.snapshot()`、各流水线 `Pipeline.stats()` + `healthy`、相机计数、下位机 `connected / state / queue_len / counters / ack_timeouts / reconnects`、故障码（CSV 为平铺求和）。
  - `soak_summary.json`（与记录文件同目录）：`version / config / out / format / started_at / ended_at / stopped_by（deadline | SIGINT | SIGTERM（第一次信号的信号名）| fault | run_state:x | error）/ duration_requested_s / duration_actual_s / interval_s / speed / model{id, source: deployed|model-dir|quick-train, temporary, backend, classes, image_size} / samples / rss{start_mb, baseline_mb, end_mb, max_mb, growth_mb, peak_growth_mb, limit_mb} / threads{baseline, running_max, end, leaked[]} / chunks_total / dropped_total / latency_p99_ms / rss_growth_mb / threads_leaked / stats / pipelines / cameras / mcu / faults_seen / startup_faults / faults_end / checks{rss_ok, threads_ok, faults_ok, running_ok, running_detail{run_state_end, chunks_grew, growth_gap_s}, dropped_ok, max_dropped} / failed_checks / passed / exit_code / error / notes / summary_path`。

## 6. 推荐开发顺序

1. P0：`config.py` → `log.py` → `cli.py serve`（空 API）→ Mock 相机/下位机 → pytest 骨架。
2. P1：`nozzle.py`（先把 64 行表测试写出来）→ `preprocess.py` → `background.py`/`segment.py`（配合 `make_synthetic.py`）→ `stitch.py` → `data/store.py`、`samples.py` → `ml/models.py`、`dataset.py`、`train.py`、`metrics.py`、`export.py`、`infer.py`（Torch）→ `cli eval` / `cli replay`。
3. P2：`mcu/protocol.py` → `mock.py` → `link.py` → `runtime/state.py` → `jobs.py` → `pipeline.py` → `decision.py` → `api/*` → `ws.py` → systemd/deploy 脚本 → `export_openapi.py` → `soak_test.py`。
4. P3：`camera/hik.py` 真机联调、`infer.py` TensorRT 实现、`build-engine` 命令、性能报告。

每完成一个模块：跑测试、更新 README 对应段落、如改了接口同步 docs/03。
