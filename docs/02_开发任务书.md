# 02 开发任务书（给 Claude Code）

前置：先读 `CLAUDE.md`、`docs/01_技术选型与架构.md`、`docs/00_原始需求/需求整理.md`。本文件规定做什么、按什么顺序、做到什么程度算完成。

## 1. 阶段划分

| 阶段 | 目标 | 交付 | 验收 |
|---|---|---|---|
| **P0 工程骨架**（半天） | 仓库可运行、可测试 | 目录结构、配置模型与持久化、日志、CLI、pytest、Mock 相机/下位机 | `pytest -q` 全绿；`cli serve` 在 Mac 上起得来，`GET /api/v1/state` 有返回 |
| **P1 识别率验证工具链**（核心） | 无硬件也能完成"采集→切图→标定→训练→评估"闭环 | camera（Hik 封装 + Mock）、vision（分割、拼接、预处理、喷头映射）、data/store（样本库全部操作）、ml（训练、指标、ONNX 导出、PyTorch 推理）、`cli eval` / `cli replay` | 用合成数据与真实样本目录跑通；`cli eval --folder` 输出交叉验证混淆矩阵；喷头映射 64 行表全过；训练→ONNX 推理一致 |
| **P2 服务化** | HMI 可对接、运行时流水线可跑 | api（docs/03 全部接口 + WS）、runtime（状态机、流水线、任务系统）、mcu（协议、TCP 链路、Mock）、systemd 单元、OpenAPI 导出 | 接口清单逐条有集成测试；Mock 相机 + Mock 下位机下跑 1 小时无丢块、无内存增长；协议编解码测试全过 |
| **P3 Jetson 联调** | 真机 | Hik 真相机、TensorRT 引擎、网络与系统调优脚本、性能报告、48 h 老化 | §4 性能指标达标 |

P1 是当前优先级，P2 其次。P3 需要硬件，由项目负责人在 Jetson 上执行，Claude Code 提供脚本与检查清单。

## 3. 模块职责与接口

### 3.1 config
- `AppConfig`（pydantic）按 docs/01 §9 分组；每个字段带范围校验；`load(path)`、`save_atomic()`；运行时修改通过 `ConfigService.update(section, patch) -> (applied, warnings)`，校验失败抛 `ConfigError(code, message, detail)`。
- 测试：越界拒绝、原子写（写入中断不损坏旧文件）。

### 3.2 camera
```python
@dataclass
class Frame:
    seq: int            # 块序号（自 start_stream 起）
    line_start: int     # 该块首行的全局行号（自 SYNC 起）
    image: np.ndarray   # (h, w, 3) uint8 RGB
    ts: float           # 单调时钟

class Camera(ABC):
    def open(self) -> None; def close(self) -> None
    def get_params(self) -> CameraParams; def set_params(self, p: CameraParams) -> CameraParams
    def awb_once(self) -> None
    def snapshot(self, height: int) -> np.ndarray
    def start_stream(self, chunk_lines: int) -> None; def stop_stream(self) -> None
    def frames(self, timeout: float) -> Iterator[Frame]
    def reset_line_counter(self) -> None
    @property
    def connected(self) -> bool
```
- `MockCamera`：从目录循环读取大图（或 `make_synthetic.py` 生成），按 `chunk_lines` 切块，模拟行频节奏（可加速）；可注入丢块/断线。
- `HikCamera`：枚举/按 IP 或序列号打开；设置 `PixelFormat=RGB8Packed`、`Width/OffsetX/Height`、`ExposureTime`、`BalanceWhiteAuto`、`AcquisitionLineRateEnable/AcquisitionLineRate`、`TriggerMode/TriggerSource`（行触发时按海康线阵的编码器/分频模块设置，节点名以 MVS 客户端实测为准）；`GevSCPSPacketSize` 取最优值；回调或拉取模式取帧转 numpy；丢块按 `nFrameNum` 断号补偿 `line_start`。无 SDK 时导入失败要给出清晰错误，不影响 Mock 路径。

### 3.3 vision
- `background.ColumnBackground.learn(frames) / distance(image) -> float32 map / save / load / adapt(image, mask)`。
- `segment.segment(image, bg, settings) -> list[Particle]`，`Particle(bbox, centroid_x, centroid_y, area, trailing_y, crop_rgba)`。
- `stitch.ChunkStitcher(overlap)`：`push(frame) -> (image, y_offset)`、`select(particles, image_h) -> list[Particle]`（§5.2 规则），并把块内 y 换算为全局行号。
- `preprocess.to_tensor(crop_rgba, image_size) -> np.ndarray(C,H,W)`，训练与推理唯一入口。
- `nozzle.NozzleMap(start_px, end_px, n=64)`：`ranges()`、`pixel_to_nozzle(x)`、`span(x0, x1, expand=0)`；`test_nozzle.py` 用 `docs/00_原始需求` 中规则生成 r=0..63 的期望表逐行比对。

### 3.4 data
- `ModelStore(root, max_models, class_names)`：`create(id, name, description)`、`delete(id)`、`backup(src, dst, overwrite)`、`list()`、`meta(id)`、`update_meta(id, **patch)`；禁止删除当前部署模型（由上层判断，store 提供 `deployed_id`）。
- `SampleRepo(model_dir)`：`add(cls, crop_rgba, meta) -> Sample`、`list(cls, include_deleted, offset, limit)`、`soft_delete(ids)`、`undo_last(cls)`（撤销最近一次删除批次，批次栈持久化到 `samples/.trash/journal.json`）、`clear(cls)`（整类软删除，作为一个批次）、`purge(older_than)`、缩略图生成；文件名含相机号、时间、序号；写入原子。

### 3.5 ml
- `Classifier` 接口：`load(model_dir)`, `predict(batch: np.ndarray) -> (probs, classes)`, `warmup()`；实现 `TrtClassifier`（TensorRT 不可用时抛明确异常）与 `TorchClassifier`。
- `train.run(model_dir, classes, cfg, progress_cb)`：按 docs/01 §6.2 配方；子进程入口 `python -m oresorter.ml.train --model-dir ... --classes ...`，进度写 `train/progress.json`，主进程轮询并转发 WS。
- `metrics.report(y_true, y_pred, classes) -> dict`（混淆矩阵、每类 P/R/F1/support、准确率、macro-F1）。
- `export.to_onnx(model, image_size, path)`、`export.build_engine(onnx_path, plan_path, image_size)`（调用 trtexec，超时 10 min）。
- `cli eval --folder DIR`：DIR 下每个子目录是一类（直接支持客户现有的 a/ b/ c/ 目录，图片可为 bmp/png/jpg，无 alpha 时用蓝底自动抠 mask）；做 5 折（样本少于 50 自动改留一法）交叉验证，打印混淆矩阵与每类指标，并保存 `eval_report.json`。

### 3.6 mcu
- `protocol.py`：帧结构、`encode(addr, cmd, payload, seq)`、`decode(buf) -> frames`（处理粘包/半包）、CRC16-MODBUS、指令与参数 ID 常量（docs/04）。
- `McuLink` 接口：`connect/close`、`send(cmd, payload, need_ack=True, timeout=0.2) -> Ack`、`send_eject(batch)`、`status` 属性、`on_event(cb)`；`TcpMcuLink` 含心跳线程、重连退避、ACK 匹配（按 seq）、链路故障回调。
- `MockMcu`：实现协议的另一端（可直接作为 asyncio TCP server 跑，也可进程内），维护参数表、状态、编码器计数、喷阀计数；支持注入"不回 ACK"、"断开"等故障用于测试。

### 3.7 runtime
- `StateMachine`：docs/01 §4.3；`transition(event)` 返回新状态或抛 `IllegalTransition`；faults 集合（code、since、detail）。
- `Pipeline`：三线程 + 环形队列；统计每块耗时、丢块数、颗粒数；处理线程异常计数与自恢复。
- `decision.decide(particle, probs, classes, blow_cfg) -> Decision(blow: bool, cls, conf)`。
- `jobs.JobManager`：`submit(job) -> id`、`get(id)`、`cancel(id)`；同类型互斥（同时只能一个 capture、一个 train）；进度与结果通过 WS 推送。
- 采样任务：在 sampling 状态下运行分割并写入 `SampleRepo`，每写一张推送 `capture_sample` 事件；上限（张数/帧数/时长）或取消时结束并恢复状态。

### 3.8 api
- 与 docs/03 一一对应；`schemas.py` 的模型字段名就是接口字段名；错误统一为 `{"error": {"code","message","detail"}}`；`request_id` 幂等缓存；静态文件挂载 `/static -> data_dir`（只读）。
- `ws.py`：`/ws/events` 广播器（状态、任务、故障、统计、采样样本、下位机状态）；`/ws/preview/{camera_id}`（JPEG 二进制帧，限频、丢旧帧，`mode=full|edges`，edges 模式按起始/结束像素合成两段并画白线）。
- `scripts/export_openapi.py` 导出 `docs/openapi.json`，CI 检查与仓库中的一致。

## 4. 验收标准（P2/P3）

| 指标 | 目标 |
|---|---|
| 512 行块处理延迟（块到达 → EJECT 发出） | p50 < 40 ms，p99 < 80 ms（Jetson，含推理） |
| 持续吞吐 | 9 kHz 行频下 1 小时丢块 = 0（Mock 与真机各测） |
| 训练 | 1000 张样本、160 px、ResNet18 ≤ 5 min；指标报告完整 |
| 部署 | 含引擎生成 ≤ 120 s；PyTorch 与 TensorRT top-1 一致率 100%，概率差 < 1e-2 |
| API | 命令类接口 p99 < 100 ms（不含等待下位机 ACK 的时间） |
| 链路 | 下位机/相机断线后 ≤ 5 s 自动重连并恢复参数；HMI WS 断线重连后状态一致 |
| 稳定性 | Mock 下 48 h 连续运行，RSS 增长 < 50 MB，无线程泄漏 |
| 测试 | `pytest -q` 全绿；接口清单每条至少一个集成测试；喷头映射 64 行表全过 |

## 5. 测试计划

- **单元**：nozzle（64 行表）、protocol（编解码、CRC、粘包/半包、错误帧）、stitch（跨块颗粒恰好处理一次；触底对象延后；超长对象告警）、segment（合成图上数量/位置/面积误差）、preprocess（确定性、尺寸）、samples（软删除/撤销/清空/批次栈持久化/并发写）、config（范围、原子写）。
- **集成**：api（每个接口的正常与错误路径，TestClient + Mock 设备）、runtime（状态机全部迁移、采样任务、训练任务、自动重部署）、mcu_link（Mock server：心跳超时置故障、重连后重发参数与 SYNC、ACK 超时重发 3 次）。
- **一致性**：train → onnx → infer；同一张图 PyTorch/ONNXRuntime/TensorRT 输出比对（TensorRT 部分仅在 Jetson 运行，用 `pytest -m jetson` 标记）。
- **老化**：`scripts/soak_test.py` 记录每分钟 RSS、队列长度、块耗时分布。

## 6. 推荐开发顺序

1. P0：`config.py` → `log.py` → `cli.py serve`（空 API）→ Mock 相机/下位机 → pytest 骨架。
2. P1：`nozzle.py`（先把 64 行表测试写出来）→ `preprocess.py` → `background.py`/`segment.py`（配合 `make_synthetic.py`）→ `stitch.py` → `data/store.py`、`samples.py` → `ml/models.py`、`dataset.py`、`train.py`、`metrics.py`、`export.py`、`infer.py`（Torch）→ `cli eval` / `cli replay`。
3. P2：`mcu/protocol.py` → `mock.py` → `link.py` → `runtime/state.py` → `jobs.py` → `pipeline.py` → `decision.py` → `api/*` → `ws.py` → systemd/deploy 脚本 → `export_openapi.py` → `soak_test.py`。
4. P3：`camera/hik.py` 真机联调、`infer.py` TensorRT 实现、`build-engine` 命令、性能报告。

每完成一个模块：跑测试、更新 README 对应段落、如改了接口同步 docs/03。
