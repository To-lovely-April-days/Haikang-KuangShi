# 03 前端接口清单（HMI ↔ 算力盒）v1

本文件是前后端契约。实现以此为准，改动必须同步更新本文件并重新导出 `docs/openapi.json`。

最近更新：2026-10-24，已按 P2b 实现同步。

## 1. 约定

- 基地址：`http://<算力盒IP>:8000/api/v1`；WebSocket：`ws://<算力盒IP>:8000/api/v1/ws/...`；静态文件：`http://<算力盒IP>:8000/static/...`。
- 内容类型 `application/json; charset=utf-8`；时间为 ISO 8601 带时区；图像尺寸单位像素；枚举值小写字符串。
- 成功：2xx + JSON 体。失败：4xx/5xx + `{"error": {"code": "PARAM_OUT_OF_RANGE", "message": "开阀时间超出范围 0~255", "detail": {...}}}`。常用 code：`VALIDATION`、`PARAM_OUT_OF_RANGE`、`NOT_FOUND`、`CONFLICT`（状态不允许/已存在/正在训练）、`DEVICE_OFFLINE`（相机/下位机离线）、`MCU_NACK`（下位机拒绝）、`MCU_TIMEOUT`、`INTERNAL`。
- 所有写操作（POST/PUT/PATCH/DELETE）可带 `request_id`（字符串，≤ 128 字符，放在 JSON 体顶层或 `X-Request-Id` 头，头优先；**超长不一定被拒绝**：`X-Request-Id` 头与自由对象请求体（如 `PUT /params/{section}`）里超过 128 字符的值按**前 128 字符截断**作键，只有带类型化请求体模型（`schemas.RequestIdBody` 及含 `request_id` 字段的请求模型，`max_length=128`）的接口超长才 400 `VALIDATION`，因此 HMI 必须自行保证 ≤ 128 字符，否则仅前 128 字符相同的两个 id 会被当成同一键回放）；幂等键为 `(method, path, request_id)`，60 s 内重复提交直接回放首次的**完整响应**（状态码、头、体），不重复执行，命中时响应头带 `X-Idempotent-Replay: 1`；错误响应（4xx/5xx）同样按 `request_id` 缓存 60 s（重试拿到的是首次结论，不会重复执行一次已失败的操作）；同键并发请求合并等待先到者完成（单次等待上限 30 s）后返回同一结果。`request_id` 不算业务字段（自由对象请求体里会被剔除）。
- 部署方式：HMI 与后端默认**同源**（HMI 工控机直接访问算力盒 `IP:8000`，或由后端 `/static` 托管 HMI 静态文件），此时不需要 CORS。HMI 跨源部署（如独立静态站点）时须在配置 `system.cors_origins` 列出来源（如 `["http://192.168.1.20"]`），非空时后端挂 `CORSMiddleware`（允许全部方法与请求头，暴露 `X-Idempotent-Replay`）；为空（默认）不挂。
- 后端是状态唯一来源：HMI 启动与 WS 重连后先 `GET /state` 全量同步；之后通过 `/ws/events` 增量更新。
- 原始需求里"点击操作按钮都要弹确认框"由 HMI 实现，后端不做二次确认。
- 枚举：`run_state ∈ stopped | running | paused | sampling | fault`；`awb_mode ∈ off | once | continuous`；`trigger ∈ internal | encoder`；`job.status ∈ queued | running | succeeded | failed | cancelled`；`job.type ∈ capture | train | deploy | valve_test | backup`。

## 3. 系统与状态

### GET /state
全量状态快照。
```json
{
  "time": "2026-10-24T16:40:00+11:00",
  "uptime_total_s": 864000,
  "run_state": "running",
  "deployed_model_id": 1,
  "cameras": [{"id": 1, "connected": true, "streaming": true, "line_rate_hz": 9000, "chunks_total": 63000, "dropped_chunks": 0, "reconnects": 0, "errors": 0, "chunks_per_s": 17.5}],
  "mcu": {"connected": true, "state": "running", "last_heartbeat_ms": 120, "encoder_count": 123456, "faults": []},
  "faults": [],
  "jobs": [{"job_id": "j-20261024-0001", "type": "train", "status": "running", "progress": 0.42, "stage": "epoch 8/30", "model_id": 2}],
  "stats": {"particles_per_min": 1200, "blown_per_min": 300, "per_class_per_min": {"A": 500, "B": 400, "C": 300, "D": 0, "E": 0, "F": 0, "G": 0},
            "chunk_latency_ms_p50": 23.5, "chunk_latency_ms_p99": 61.0, "chunk_latency_ms_max": 74.2,
            "chunks_total": 63000, "dropped_chunks": 0, "particles_total": 72000, "blown_total": 18000,
            "per_class_total": {"A": 30000, "B": 24000, "C": 18000, "D": 0, "E": 0, "F": 0, "G": 0},
            "since": "2026-10-24T15:40:00+11:00", "elapsed_s": 3600.0},
  "pipeline": {"camera_id": 1, "mode": "sort", "running": true, "queue_len": 0, "queue_dropped": 0, "send_queue_len": 0, "send_dropped": 0,
               "chunks": 63000, "errors": 0, "consecutive_errors": 0, "blown": 18000, "eject_sent": 18000, "eject_failed": 0, "eject_skipped": 3,
               "last_latency_ms": 23.5, "blow_enabled": true, "predict_errors": 0, "consecutive_predict_errors": 0,
               "frames": 63000, "dropped": 0, "resets": 0, "deferred": 120, "skipped_seen": 118, "truncated": 2, "selected": 72000, "lost": 0},
  "version": "0.1.0"
}
```
- `stats`：`*_per_min` 为滑动窗口（默认 60 s）折算后四舍五入的 **int**；`chunk_latency_ms_p50 / p99 / max` 为 float（最近 2000 块）；`*_total` 与 `since / elapsed_s` 自本次 start（或服务启动）累计。`per_class_per_min` / `per_class_total` **总是包含全部已配置类别**（未出现为 0，顺序同 `system.class_names`），未配置但出现过的类别追加在后；非 `running` 状态仍返回上次 start 以来的累计值。
- `pipeline`：第一条流水线（多相机时为配置里的第一台；采样期间为 capture 流水线）的 `Pipeline.stats()`，没有流水线在跑时为 `null`；多相机各流水线统计见 `GET /run/stats.pipelines`。字段 = 拼接器统计 `frames / dropped / resets / deferred / skipped_seen / truncated / selected / lost`（docs/01 §5.2）+ `camera_id / mode (sort|capture) / running / queue_len / queue_dropped / send_queue_len / send_dropped / chunks / errors / consecutive_errors / blown / eject_sent / eject_failed / eject_skipped（决定吹但落在起止像素外、映射不到喷头）/ last_latency_ms / blow_enabled`；sort 模式另有 `predict_errors / consecutive_predict_errors`，capture 模式另有 `samples`。
- `faults[]` 元素：`{"code": "...", "since": "...", "detail": "..."}`。任何故障置位即进入 `fault`（后端自动下发 STOP、停流水线、取消采样 / 喷阀检测任务），全部清除后回到 `stopped`，需人工 start（docs/01 §4.3）。`code` 清单：
  - `CAMERA_{id}_DISCONNECTED`（按相机编号：打开失败 / 掉线 / 开流失败；重连后清除）、`CAMERA_{id}_TIMEOUT`（运行中连续 `pipeline.frame_timeout_s` 无帧而相机仍在线；流水线再收到帧时清除，流水线已停且相机在线时由设备巡检（2 s）清除，`POST /run/stop` 也清除）；
  - `MCU_DISCONNECTED`（断线、心跳 / ACK 超时；重连后清除）、`MCU_EVENT_0001`（下位机 level=2 事件，后四位为十六进制事件码，见 docs/04 §7；下位机重连后清除）、`MCU_FAULT_0001`（下位机 STATUS 故障位图 bit n 置位，后四位为十六进制 n，位清除即清除；**目前只有 Mock 链路会产生**，真机 `TcpMcuLink` 的位图故障只出现在 `mcu.faults` 文字列表、不进顶层 `faults`，两者统一前 HMI 以 `mcu.faults` 为准）；
  - `PIPELINE_ERROR`（流水线连续 20 块处理失败，或采样后恢复分选流水线失败；置位即停流水线并进入 fault，操作员 `POST /run/stop` 视为确认并清除，全部故障清除后回到 stopped 方可再 start）、`CLASSIFIER_ERROR`（分类器连续 20 块推理失败，而不是静默不吹；**粘性**，重新部署 / 切换分类器后清除）、`MODEL_LOAD_FAILED`（开机加载持久化的部署模型失败，`deployed_model_id` 被清空；重新部署后清除）。
- `mcu`：`{connected, state, encoder_count, last_heartbeat_ms, rtt_ms, faults: [文字], queue_len, belt_speed, pressure | null, counters: {eject_rx, eject_done, eject_dropped, period_ms}, reconnects, ack_timeouts}`。
- `version`：后端**包版本** `oresorter.__version__`（同 `GET /health` 与 `GET /system/info`；当前 0.1.0，不是配置项 `system.version`，后者暂无读者）。

### GET /health → `{"ok": true, "version": "0.1.0"}`（`oresorter.__version__`）
### GET /system/info → `{"version", "hostname", "platform", "python", "data_dir", "disk_total_mb", "disk_free_mb", "cpu_percent", "mem_percent", "temperatures_c": {传感器: ℃}, "gpu_percent": float | null（仅 Jetson）, "ips": {网口: [IPv4]}, "pid", "preview_max_fps"}`；`preview_max_fps` 即配置 `system.preview_max_fps`，是 WS 预览 `fps` 参数的上限（§7）。
### POST /system/save → `{"saved": true, "backup_path": "..."}`（配置已随每次修改即时持久化，此接口刷运行时长、显式落盘并导出备份 `config.backup.json`）。
### POST /system/shutdown / POST /system/reboot → `{"accepted": true, "action": "poweroff" | "reboot"}`：先 `stop()`（取消采样、下发 STOP、停流水线），2 s 后在后台执行 `systemctl poweroff|reboot`。**只有配置 `system.allow_power_actions=true`**（`jetson.yaml` 为 true，`default.yaml` / 开发机为 false；兼容环境变量 `ORESORTER_ALLOW_POWER=1`）时才真正执行，否则只记日志，响应相同。

## 4. 运行控制

### POST /run/start | /run/pause | /run/stop
- 请求体可空或 `{"request_id": "..."}`。
- 成功 → `{"run_state": "running", "mcu_ack": true}`。
- `start`（stopped → running）：前置检查（含列背景预检）→ 取消进行中的喷阀循环检测任务 → 清零统计 → SYNC（下位机编码器清零）+ 全部相机行号归零 → 启动流水线 → RUN；`paused → running` 只发 RUN 并恢复吹气，**不重新 SYNC、不重置行号**（docs/01 §5.5）。`pause`：PAUSE → 流水线停吹（继续采集 / 分类 / 统计）。
- 失败 409 `CONFLICT`：`detail = {"state": 当前状态, "reasons": [...]}`，`reasons` 取自 `NO_MODEL_DEPLOYED / CAMERA_DISCONNECTED / MCU_DISCONNECTED / SAMPLING_IN_PROGRESS / IN_FAULT / ALREADY_RUNNING / NOT_RUNNING / NOT_SAMPLING / BACKGROUND_NOT_LEARNED`，如 `["NO_MODEL_DEPLOYED", "CAMERA_DISCONNECTED"]`。`BACKGROUND_NOT_LEARNED`：`capture.bg_mode=column` 而某相机的列背景未学习（`detail.camera_id`；用 `cli learn-bg` 学习），在 SYNC 之前预检、不会先清零编码器再失败；相机开流失败归入 `CAMERA_DISCONNECTED`（`detail.camera_id`，同时置故障 `CAMERA_{id}_DISCONNECTED`）。
- `fault` 状态下 `POST /run/stop` **不是 409**：返回 200 `{"run_state": "fault", "mcu_ack": true|false}`（STOP 已转发给下位机，`mcu_ack=false` 表示 STOP 下发失败、只记日志；故障不清除，恢复后状态回到 `stopped`，需人工再 start）。`sampling` 状态下 `POST /run/stop` **先取消采集任务**（最多等 3 s 收尾）再下发 STOP、回到 `stopped`。幂等调用（running 再 start、paused 再 pause、stopped 再 stop）返回 200 当前状态。

### GET /run/stats → `state.stats` 的全部字段 + `since_start`（`{"since", "elapsed_s", "chunks_total", "dropped_chunks", "particles_total", "blown_total", "per_class_total"}`，自本次 start 以来的累计）+ `pipelines`（`{"<camera_id>": Pipeline.stats()}`，字段见 §3 `pipeline`；没有流水线在跑时为 `{}`）。

## 5. 参数

### GET /params
```json
{
  "valve": {"open_time": 255, "hold": 255, "reblow": 20, "delay": 376},
  "clean": {"time": 20, "period": 200, "count": 5, "enabled": false},
  "feed": {"speeds": [50, 50, 50, 50, 50, 50, 50, 50, 50]},
  "outputs": {"conveyor": false, "valve": false, "feeder": false},
  "blow": {"classes": ["C"], "min_confidence": 128, "size_min": 0, "size_max": 255},
  "capture": {"bg_mode": "column", "bg_color": [0, 0, 255], "bg_threshold": 40.0, "erode_px": 1, "dilate_px": 2, "min_area_px": 400, "max_area_px": 2000000, "margin_px": 8, "split_touching": false, "bg_learn_frames": 20, "bg_adapt_rate": 0.0},
  "limits": {"valve": {"open_time": [0, 255], "hold": [0, 255], "reblow": [0, 50], "delay": [0, 800]}, "clean": {"time": [0, 200], "period": [0, 200], "count": [0, 5]},
             "feed": {"speed": [0, 100], "count": 9}, "valve_test": {"hole": [1, 64]},
             "blow": {"min_confidence": [0, 255], "size_min": [0, 255], "size_max": [0, 255]},
             "capture": {"bg_threshold": [0, 255], "erode_px": [0, 50], "dilate_px": [0, 50], "min_area_px": [0, 16000000], "max_area_px": [1, 16000000], "margin_px": [0, 200], "bg_learn_frames": [1, 1000], "bg_adapt_rate": [0, 0.1]}}
}
```
`limits` 由后端配置生成，HMI 用它做输入范围，不要在前端写死。`valve_test.hole` 为 `[1, 相机数 × 每相机喷头数]`（配置项 `valve_test.hole=0` 仅表示“未选”，不是合法输入）；`feed.count` 为给料路数（`feed.speeds` 长度必须等于它）。

### PUT /params/valve | /params/clean | /params/feed | /params/outputs | /params/blow | /params/capture
- `section` 路径参数在 OpenAPI 中是枚举 `valve | clean | feed | outputs | blow | capture`（`schemas.ParamSection` Literal，供 HMI 生成客户端）；其它值 → 404 `NOT_FOUND`。
- 请求体：该分组的部分或全部字段（部分更新；`request_id` 不算业务字段）。
- 响应：`{"applied": {...该分组全部当前值...}, "mcu_ack": true, "warnings": []}`。`mcu_ack` 为 `null` 表示该分组不下发下位机（blow、capture）；`false` 表示已持久化但下位机未确认（超时 / 断线），此时 `warnings` 含说明（如 `下位机未确认（…），已保存，重连后自动补发`），重连后后端补发并以 WS `param_sync` 事件通知最终结果；下位机 NACK → 配置回滚并 502 `MCU_NACK`。`blow` 立即作用于运行中流水线；`capture` 热更新运行中流水线的分割参数（column 背景缺失时 `warnings` 说明未能应用）。
- 越界 → 400 `PARAM_OUT_OF_RANGE`（单字段）/ `VALIDATION`（跨字段规则），不做部分应用。

## 6. 喷阀检测

- `POST /valve/test/single` 体 `{"hole": 376}` → `{"accepted": true}`；孔位范围见 `limits.valve_test.hole`（`[1, 相机数 × 64]`），越界 400 `PARAM_OUT_OF_RANGE`；成功后 `hole` 持久化到配置 `valve_test.hole`。
- `POST /valve/test/cycle` 体 `{"from": 1, "to": 64, "interval_ms": 200}` → 200 `{"job_id": "..."}`（后台任务 `type=valve_test`，可取消；`from` / `to` 同样按 `hole` 范围校验，`from > to` → 400 `VALIDATION`，`interval_ms` 1~65535）。
- `POST /valve/test/stop` → `{"stopped": true}`（取消循环检测任务并下发 VALVE_TEST_STOP）。
- `POST /valve/reset` → `{"accepted": true, "mcu_ack": true}`。
- 喷阀检测 / 复位只允许 `stopped` 与 `fault`：在 `running` / `paused` / `sampling` 下均返回 409 `CONFLICT`，`detail.reasons` 为 `[ALREADY_RUNNING]`（running 与 paused——paused 期间让下位机进 VALVE_TEST 会与后端状态不一致）或 `[SAMPLING_IN_PROGRESS]`（sampling）。点击运行（`POST /run/start`）会先取消进行中的循环检测任务（任务收尾下发 VALVE_TEST_STOP）。

## 7. 相机

### GET /cameras
```json
[{"id": 1, "name": "相机1", "model": "MV-CL043-A1GC", "serial": "...", "ip": "192.168.10.10", "connected": true, "streaming": false, "nozzles": 64}]
```
`streaming`：相机是否正在出流（运行 / 采样 / 有预览连接时为 true）。

### GET /cameras/{id}/params（查询，从相机实时读取）
```json
{"awb_mode": "once", "exposure_us": 50.0, "width": 4096, "offset_x": 0, "height": 4096, "runtime_chunk_lines": 512,
 "start_px": 0, "end_px": 4096, "nozzles": 64, "line_rate_hz": 9000, "trigger": "internal",
 "limits": {"exposure_us": [3, 10000], "width": [64, 4096], "height": [64, 4096], "line_rate_hz": [100, 9000],
            "runtime_chunk_lines": [128, 1024], "offset_x": [0, 4032], "px": [0, 4096]}}
```
相机侧字段实时读自相机，`start_px / end_px / runtime_chunk_lines / nozzles` 来自算力盒配置（`nozzles` 为部署项，只读）；相机离线 → 503 `DEVICE_OFFLINE`（`detail.camera_id`）。

### PUT /cameras/{id}/params（下发）
- 部分更新，可编辑字段 `awb_mode / exposure_us / width / offset_x / height / runtime_chunk_lines / start_px / end_px / line_rate_hz / trigger`（其它字段 → 400 `VALIDATION`）；响应 `{"applied": {...相机字段 + start_px / end_px / runtime_chunk_lines...}, "warnings": [...]}`。
- 先整体校验并持久化（越界 → 400 `PARAM_OUT_OF_RANGE`，不保存、不下发）。`start_px / end_px / runtime_chunk_lines` 只保存在算力盒：起止像素（及 `offset_x`）变化立即热更新运行中流水线的喷头映射；相机侧字段在相机在线时写入相机，相机按步进对齐过的值回写配置并在 `warnings` 说明（如 `相机按步进对齐了部分参数: exposure_us → 50.5`）；相机拒绝参数时已保存但 `warnings` 说明未生效。
- 相机**离线**时不再是 503：校验通过即持久化并在重连后下发，响应 200 且 `warnings` 含 `相机离线，参数已保存，连接后生效`；越界仍 400 不保存。运行中修改 `width / offset_x / height` 时 `warnings` 提示"图像尺寸/块高变化需重新开始运行后生效"；`runtime_chunk_lines` 同样要重新开始运行后才生效（流水线块高在启动时固定），但请求**只含它**（不带任何相机侧字段）时当前不给 warning，HMI 自行提示。
- `GET /cameras/{id}/params` 与 `POST /cameras/{id}/awb-once` 在相机离线时仍为 503 `DEVICE_OFFLINE`。

### POST /cameras/{id}/snapshot（单次采集）
- 体 `{"height": 4096, "max_width": 2000, "overlay": false}`（均可省略：`height` 缺省取相机配置 `height`，范围 1~4096；`max_width` 16~16384，越界 400）；响应 `{"image_url": "/static/snapshots/cam1_20261024_164012_123456.jpg", "width": 4096, "height": 4096, "warnings": []}`。`overlay=true` 时叠画分割框（用于调采集设置）并另返回 `count`（颗粒数；`bg_mode=column` 而背景未学习 → 409 `CONFLICT`，`detail.reasons=["BACKGROUND_NOT_LEARNED"]`、`detail.camera_id`，与 §4 start 同口径）。
- 停止状态下向相机单次采集 `height` 行（相机离线 → 503）；**运行 / 采样中**不打断采集，由流水线的连续块拼到请求高度（等待上限约 3 × height / line_rate，夹在 1~5 s），时限内拼不满时响应 `height` 小于请求值并在 `warnings` 说明。`width / height` 为原图尺寸，图片文件本身按 `max_width` 等比缩放。`snapshots/` 只保留最近 `system.max_snapshots_kept`（默认 50）张。

### WS /ws/preview/{id}?mode=full&fps=5&quality=70&max_width=1000&edge_px=500（连续采集）
- 查询参数（默认值如上）：`mode ∈ full | edges`；`fps` 1~`system.preview_max_fps`（上限见 `GET /system/info.preview_max_fps`，默认 10）；`quality` 10~100；`max_width` 16~16384；`edge_px` 1~相机宽（`width`）。**越界一律拒绝、不夹断**：连接接受后先发文本 `{"type": "error", "code": "PARAM_OUT_OF_RANGE" | "VALIDATION" | "NOT_FOUND", "message": "...", "detail": {...}, "ts": "..."}`，再以 1008 关闭。`detail` 随 code 不同：`PARAM_OUT_OF_RANGE` 为 `{"field", "input", "range": [lo, hi]}`；`VALIDATION`（`mode` 非法）为 `{"field", "input"}`；`NOT_FOUND`（相机不存在）为 `{"camera_id"}`。
- `mode=full`：整幅等比缩放到 `max_width` 的 JPEG；`mode=edges`：把 `[0, edge_px)` 与 `[w−edge_px, w)` 两段横向拼成一幅（原始需求的 1~500 与 3597~4096 两段式），**输出宽度恒为 2×edge_px，不按 `max_width` 缩放**，并在 `start_px` / `end_px` 处画 2 px 白竖线：传感器坐标减 `offset_x` 映射到帧局部列号，起始线占有效区首 2 列、结束线占有效区末 2 列（`end_px` 为开区间），落在两段之外的不画。
- 每帧先发一条文本消息 `{"type": "frame", "seq": 12, "w": 1000, "h": 512, "start_px": 0, "end_px": 4096, "ts": "..."}`（`w / h` 为输出图尺寸），紧接一条二进制消息（JPEG）。
- 服务端按 `fps` 限频，每个发送时隙只发**最新**一帧（期间到达的旧帧丢弃，不堆积）；相机离线（取不到帧且 `connected=false`）→ 发 `{"type": "error", "code": "DEVICE_OFFLINE", ...}` 后以 1011 关闭。客户端关闭连接即停止；`sampling` / `running` 期间预览与流水线共用帧、不中断采集，否则后端按需开流、最后一个预览连接关闭时停流。预览通道不处理客户端消息（无需 pong）。

## 9. 样本采集与管理

### POST /models/{id}/classes/{cls}/capture（连续采集 / 追加图片）
- 体 `{"camera_id": 1, "max_samples": 200, "max_frames": 50, "timeout_s": 120}`（`max_samples` 1~100000、`timeout_s` 1~86400、`max_frames` ≥ 1 或 `null` = 不限）；任一上限到达或取消即结束，被截断的半颗矿石不进样本库。
- 前置：`run_state ∈ {stopped, paused}`，否则 409；相机离线 → 503；类别未定义 → 400；磁盘剩余 < `system.min_free_disk_mb` → 409。期间状态变为 `sampling`（采样独占相机：来源为 `paused` 时挂起分选流水线），结束后恢复原状态（回到 `paused` 时重建不吹的分选流水线，不重置行号）。
- 响应 200 `{"job_id": "..."}`（`type=capture`；任务 `result = {"count", "frames", "stop_reason": "max_samples" | "max_frames" | "timeout" | "cancelled" | "store_error" | "pipeline_stopped", "error"}`）；每切出一张小图推送 WS `capture_sample` 事件（HMI 实时刷新缩略图）。

{"total": 320, "items": [
  {"sample_id": "1/A/cam1_20261024_164012_000123", "thumb_url": "/static/models/1/thumbs/A/cam1_20261024_164012_000123.jpg",

## 10. 训练与任务

### POST /models/{id}/train
- 体 `{"classes": ["A", "B", "C"]}`（省略 = 该模型所有有样本的类别）。
- 响应 202 `{"job_id": "..."}`；已有训练任务（任一模型）→ 409；该模型正在部署或正作为备份目标 → 409（训练会重写 `train/` 产物，不能与读取它们的部署并行）；某类样本不足 → 400 `VALIDATION`，`detail.insufficient = {"B": 7}`；`classes` 为空 / 重复 / 含未知类别、或有样本的类别少于 2 个 → 400 `VALIDATION`。
- 训练完成：`metrics.json` 更新；若该模型为当前部署模型则自动触发 deploy（原始需求），WS 推送 `job` 与 `state`。

### GET /jobs/{job_id}
```json
{"job_id": "...", "type": "train", "model_id": 2, "status": "running", "progress": 0.42, "stage": "epoch 8/30 val_f1=0.93",
 "message": null, "created_at": "...", "started_at": "...", "finished_at": null, "result": null, "meta": {"classes": ["A", "B", "C"]}}
```
- `created_at` 为提交时刻（排队中 `started_at` 为 null）；`meta` 为提交时附带的信息（如训练类别、采样参数、备份目标），各任务类型自定。
- 训练成功时 `result = {"metrics_summary": {"val_accuracy": 0.97, "macro_f1": 0.96}, "artifacts": {"onnx": true, "engine": false}, "classes": ["A", "B", "C"], "epochs": 18, "duration_s": 132.5}`；若该模型为当前部署模型，另含 `redeploy_job_id`（自动重部署任务 id）或 `redeploy_error`（重部署未能提交的原因）。`result.artifacts` 为 `{"onnx": bool, "engine": bool}`（任务层固定 `engine=false`，引擎由 deploy 任务生成）；`best_epoch / sample_counts / stop_reason / artifacts.onnx_error` 等完整信息**不在** `result` 中，经 `GET /models/{id}/metrics`（`metrics.json`）获取。失败时 `message` 为原因，训练任务的 `message` 取子进程写的 `train/error.json` 的 `message`。
- 取消：`status=cancelled`；**任务函数正常返回但取消已请求时 `status=cancelled` 且 `result` 保留**（例如采样任务被取消时已写入的样本数）。`progress` 只在 `succeeded` 时强制为 1。
- 各类型任务成功时的 `result`：`train` 见上；`deploy` 见 §8；`capture` 见 §9；`backup` = `{"target_id", "source_id", "name"}`；`valve_test` = `{"stopped": true}`。

- `GET /jobs?active=true` 列表（`active=false` 含最近结束的 200 条历史）；`POST /jobs/{job_id}/cancel` → `{"cancelled": true}`（不存在 / 已结束 → `false`）；`GET /jobs/{job_id}` 不存在 → 404。

## 11. WebSocket 事件流 /ws/events

连接后立即收到一条 `state` 全量事件（与 `GET /state` 同结构，可作为重连后的全量同步），之后按需推送。消息格式 `{"type": "...", "ts": "...", "data": {...}}`：

| type | 触发 | data |
|---|---|---|
| `state` | 状态迁移、故障置位/清除（每次变化恰好一条）、部署模型切换、类别配置修改，及每 5 s 心跳 | 同 `GET /state` |
| `stats` | 每 1 s（running 时） | 同 `state.stats` |
| `job` | 任务创建/开始/进度/完成/失败/取消 | 同 `GET /jobs/{id}`。进度事件限频：同一任务默认 ≥ 0.1 s 一条，`stage` 变化与结束事件不限频，被压下的最后一次进度在间隔到期后补发（结束前必补发），HMI 不会长时间看到陈旧进度 |
| `capture_sample` | 采样切出一张小图 | `{"model_id": 1, "class": "A", "sample": {...样本项...}, "count": 57}` |
| `param_sync` | 参数下发下位机的最终结果 | `{"section": "valve", "mcu_ack": true, "error": null}` |
| `fault` | 故障产生/清除 | `{"code": "MCU_DISCONNECTED", "active": true, "detail": "..."}` |
| `mcu` | 下位机状态变化（连接 / 断开 / 故障 / 状态上报立即发，COUNTERS 等限频 1 s） | 同 `state.mcu` |

- 存活检测：服务端每 5 s 发**应用层**文本 `{"type": "ping", "ts": "..."}`，客户端必须回应用层文本 `{"type": "pong"}`（任何客户端文本消息都算存活）；WebSocket **协议层** ping/pong 由 uvicorn 处理、到不了应用层，只回协议层 pong 无效。连续 15 s 没有收到任何客户端消息以 1001 断开。断线后客户端重连并重新 `GET /state`（重连时的首条 `state` 本身就是全量，可代替一次 GET）。
- 顺序保证：连接时先订阅再取快照；首条 `state` 之后，发布时刻（`ts`）早于该快照的**全量型**事件（`state / stats / mcu`）会被丢弃，避免把 HMI 状态回退到旧值；增量型事件（`job / capture_sample / param_sync / fault`）一律保留。每连接发送队列 200 条，满时丢最旧。
- `job` 事件限频：同一任务进度事件 ≥ 0.1 s 一条，`stage` 变化与结束事件不限频，被压下的最后一次进度在间隔到期后补发（结束前必补发）；`job.data` 字段同 `GET /jobs/{id}`（含 `created_at`、`meta`）。
