# 03 前端接口清单（HMI ↔ 算力盒）v1

本文件是前后端契约。实现以此为准，改动必须同步更新本文件并重新导出 `docs/openapi.json`。

## 1. 约定

- 基地址：`http://<算力盒IP>:8000/api/v1`；WebSocket：`ws://<算力盒IP>:8000/api/v1/ws/...`；静态文件：`http://<算力盒IP>:8000/static/...`。
- 内容类型 `application/json; charset=utf-8`；时间为 ISO 8601 带时区；图像尺寸单位像素；枚举值小写字符串。
- 成功：2xx + JSON 体。失败：4xx/5xx + `{"error": {"code": "PARAM_OUT_OF_RANGE", "message": "开阀时间超出范围 0~255", "detail": {...}}}`。常用 code：`VALIDATION`、`PARAM_OUT_OF_RANGE`、`NOT_FOUND`、`CONFLICT`（状态不允许/已存在/正在训练）、`DEVICE_OFFLINE`（相机/下位机离线）、`MCU_NACK`（下位机拒绝）、`MCU_TIMEOUT`、`INTERNAL`。
- 所有写操作（POST/PUT/PATCH/DELETE）可带 `request_id`（字符串，放在 JSON 体或 `X-Request-Id` 头）；60 s 内重复的 `request_id` 直接返回首次结果，不重复执行。
- 后端是状态唯一来源：HMI 启动与 WS 重连后先 `GET /state` 全量同步；之后通过 `/ws/events` 增量更新。
- 原始需求里"点击操作按钮都要弹确认框"由 HMI 实现，后端不做二次确认。
- 枚举：`run_state ∈ stopped | running | paused | sampling | fault`；`awb_mode ∈ off | once | continuous`；`trigger ∈ internal | encoder`；`job.status ∈ queued | running | succeeded | failed | cancelled`；`job.type ∈ capture | train | deploy | valve_test`。

## 3. 系统与状态

### GET /state
全量状态快照。
```json
{
  "time": "2026-10-24T16:40:00+11:00",
  "uptime_total_s": 864000,
  "run_state": "running",
  "deployed_model_id": 1,
  "cameras": [{"id": 1, "connected": true, "streaming": true, "line_rate_hz": 9000, "chunks_per_s": 17.5, "dropped_chunks": 0}],
  "mcu": {"connected": true, "state": "running", "last_heartbeat_ms": 120, "encoder_count": 123456, "faults": []},
  "faults": [],
  "jobs": [{"job_id": "j-20261024-0001", "type": "train", "status": "running", "progress": 0.42, "stage": "epoch 8/30", "model_id": 2}],
  "stats": {"particles_per_min": 1200, "blown_per_min": 300, "per_class_per_min": {"A": 500, "B": 400, "C": 300}, "chunk_latency_ms_p99": 61}
}
```
`faults[]` 元素：`{"code": "CAMERA_DISCONNECTED", "since": "...", "detail": "..."}`。

### GET /health → `{"ok": true, "version": "1.0.0"}`
### GET /system/info → 版本、磁盘剩余、温度、GPU/CPU 占用、网口 IP。
### POST /system/save → `{"saved": true}`（配置已随每次修改即时持久化，此接口做显式落盘并导出备份 `config.backup.json`）。
### POST /system/shutdown / POST /system/reboot → `{"accepted": true}`，先停机再执行。

## 4. 运行控制

### POST /run/start | /run/pause | /run/stop
- 请求体可空或 `{"request_id": "..."}`。
- 成功 → `{"run_state": "running", "mcu_ack": true}`。
- 失败 409 `CONFLICT`：`detail.reasons` 如 `["NO_MODEL_DEPLOYED", "CAMERA_DISCONNECTED", "MCU_DISCONNECTED", "SAMPLING_IN_PROGRESS"]`。

### GET /run/stats → 与 `state.stats` 相同结构，另含自本次 start 以来的累计计数。

## 5. 参数

### GET /params
```json
{
  "valve": {"open_time": 255, "hold": 255, "reblow": 20, "delay": 376},
  "clean": {"time": 20, "period": 200, "count": 5, "enabled": false},
  "feed": {"speeds": [50, 50, 50, 50, 50, 50, 50, 50, 50]},
  "outputs": {"conveyor": false, "valve": false, "feeder": false},
  "blow": {"classes": ["C"], "min_confidence": 128, "size_min": 0, "size_max": 255},
  "capture": {"bg_mode": "column", "bg_threshold": 40, "erode_px": 1, "dilate_px": 2, "min_area_px": 400, "max_area_px": 2000000, "margin_px": 8, "split_touching": false},
  "limits": {"valve": {"open_time": [0, 255], "hold": [0, 255], "reblow": [0, 50], "delay": [0, 800]}, "clean": {"time": [0, 200], "period": [0, 200], "count": [0, 5]}, "feed": {"speed": [0, 100]}, "valve_test": {"hole": [0, 768]}}
}
```
`limits` 由后端配置生成，HMI 用它做输入范围，不要在前端写死。

### PUT /params/valve | /params/clean | /params/feed | /params/outputs | /params/blow | /params/capture
- 请求体：该分组的部分或全部字段（部分更新）。
- 响应：`{"applied": {...该分组全部当前值...}, "mcu_ack": true, "warnings": []}`。`mcu_ack` 为 `null` 表示该分组不下发下位机（blow、capture）；`false` 表示已持久化但下位机未确认，最终结果通过 WS `param_sync` 事件通知。
- 越界 → 400 `PARAM_OUT_OF_RANGE`，不做部分应用。

## 6. 喷阀检测

- `POST /valve/test/single` 体 `{"hole": 376}` → `{"accepted": true}`；孔位范围见 `limits.valve_test.hole`。
- `POST /valve/test/cycle` 体 `{"from": 1, "to": 64, "interval_ms": 200}` → `{"job_id": "..."}`（后台任务，可取消）。
- `POST /valve/test/stop` → `{"stopped": true}`。
- `POST /valve/reset` → `{"accepted": true, "mcu_ack": true}`。
- 以上在 `running` 状态下返回 409。

## 7. 相机

### GET /cameras
```json
[{"id": 1, "name": "相机1", "model": "MV-CL043-A1GC", "serial": "...", "ip": "192.168.10.10", "connected": true, "nozzles": 64}]
```

### GET /cameras/{id}/params（查询，从相机实时读取）
```json
{"awb_mode": "once", "exposure_us": 50.0, "width": 4096, "offset_x": 0, "height": 4096, "runtime_chunk_lines": 512,
 "start_px": 0, "end_px": 4096, "line_rate_hz": 9000, "trigger": "internal",
 "limits": {"exposure_us": [3, 10000], "width": [64, 4096], "height": [64, 4096], "px": [0, 4096], "line_rate_hz": [100, 9000]}}
```
### PUT /cameras/{id}/params（下发）
- 部分更新；响应 `{"applied": {...}, "warnings": ["line_rate 超过当前像素格式上限，已按 9000 下发"]}`。
- `start_px/end_px` 保存在算力盒并立即影响喷头映射；相机参数写入相机并持久化。
- 相机离线 → 503 `DEVICE_OFFLINE`。

### POST /cameras/{id}/awb-once → `{"applied": true}`（做一次白平衡并锁定为 `off`）。
### GET /cameras/{id}/nozzle-map
```json
{"start_px": 0, "end_px": 4096, "nozzles": 64, "quotient": 64, "remainder": 0,
 "ranges": [{"nozzle": 1, "px_from": 0, "px_to": 63}, {"nozzle": 2, "px_from": 64, "px_to": 127}]}
```
### POST /cameras/{id}/snapshot（单次采集）
- 体 `{"height": 4096, "max_width": 2000, "overlay": false}`；响应 `{"image_url": "/static/snapshots/cam1_20261024_164012.jpg", "width": 4096, "height": 4096}`。`overlay=true` 时叠画分割框（用于调采集设置）。

### WS /ws/preview/{id}?mode=full&fps=5&quality=70（连续采集）
- `mode=full`：整幅缩放后的 JPEG；`mode=edges`：按原始需求把起始段（1~500）与结束段（3597~4096）拼成一幅图，并在 `start_px`/`end_px` 位置画白线；段宽可用 `edge_px=500` 调整。
- 每帧先发一条文本消息 `{"type": "frame", "seq": 12, "w": 1000, "h": 512, "start_px": 0, "end_px": 4096, "ts": "..."}`，紧接一条二进制消息（JPEG）。
- 服务端限频（最大 `system.preview_max_fps`），发送队列满时丢旧帧；客户端关闭连接即停止。`sampling`/`running` 期间预览与流水线共用帧，不中断采集。

## 8. 模型（方案）

### GET /models
```json
[{"id": 1, "name": "模型1", "description": "文本", "created_at": "...", "trained_at": "...", "deployed": true,
  "algo": "cnn-resnet18", "image_size": 160,
  "classes": [{"name": "A", "sample_count": 320, "enabled": true}, {"name": "B", "sample_count": 0, "enabled": false}],
  "metrics_summary": {"val_accuracy": 0.97, "macro_f1": 0.96}}]
```
未创建的编号也返回（`created_at` 为 null），便于 HMI 固定显示 1~N（N = `system.max_models`）。

- `GET /models/current` → 当前部署模型（同上结构），无则 `null`。
- `POST /models/{id}` 体 `{"name": "模型1", "description": ""}` → 201 新建目录结构；已存在 → 409。
- `PATCH /models/{id}` 体 `{"description": "..."}`。
- `DELETE /models/{id}` → 删除全部参数与图片；当前部署的模型 → 409。
- `POST /models/{id}/backup` 体 `{"target_id": 3, "overwrite": false}` → `{"job_id": "..."}`（含图片整目录复制，大目录较慢，走任务）。
- `POST /models/{id}/deploy` → `{"job_id": "..."}`；任务完成后 `state.deployed_model_id` 更新并持久化（开机沿用）。未训练 → 409。
- `GET /models/{id}/metrics` → `metrics.json` 全文（混淆矩阵 `{"labels": [...], "matrix": [[...]]}`、每类 P/R/F1/support、训练曲线）。

### GET /config/classes → `{"class_names": ["A","B","C","D","E","F","G"], "max_models": 7}`
### PUT /config/classes（可配置项，改名需所有模型未训练或确认重训）

## 9. 样本采集与管理

### POST /models/{id}/classes/{cls}/capture（连续采集 / 追加图片）
- 体 `{"camera_id": 1, "max_samples": 200, "max_frames": 50, "timeout_s": 120}`；任一上限到达或取消即结束。
- 前置：`run_state ∈ {stopped, paused}`，否则 409；期间状态变为 `sampling`，结束后恢复。
- 响应 `{"job_id": "..."}`；每切出一张小图推送 WS `capture_sample` 事件（HMI 实时刷新缩略图）。

### GET /models/{id}/classes/{cls}/samples?offset=0&limit=100&include_deleted=false
```json
{"total": 320, "items": [
  {"sample_id": "1/A/cam1_20261024_164012_000123", "thumb_url": "/static/models/1/thumbs/A/cam1_20261024_164012_000123.jpg",
   "image_url": "/static/models/1/samples/A/cam1_20261024_164012_000123.png", "created_at": "...", "camera_id": 1,
   "bbox": [1200, 340, 180, 150], "area_px": 15321, "deleted": false}]}
```
- `DELETE /samples/{sample_id}` → 软删除 `{"deleted": true, "undo_batch": "b-17"}`；体可带 `{"ids": [...]}` 批量（用 `POST /samples/delete`）。
- `POST /samples/{sample_id}/restore` → `{"restored": true}`。
- `POST /models/{id}/classes/{cls}/undo-delete` → 撤销该类最近一次删除批次 `{"restored": 12}`；无可撤销 → 404。
- `DELETE /models/{id}/classes/{cls}/samples` → 清空该类（软删除为一个批次，可撤销一次）`{"deleted": 320, "undo_batch": "b-18"}`。
- `sample_id` 里的 `/` 在 URL 中需编码为 `%2F`。

### POST /capture/preview
- 体 `{"camera_id": 1, "settings": {...可选，临时覆盖采集设置...}}` → `{"image_url": ".../overlay.jpg", "particles": [{"bbox": [..], "area_px": 1234}], "count": 37}`，用于边调参数边看分割效果。

## 10. 训练与任务

### POST /models/{id}/train
- 体 `{"classes": ["A", "B", "C"]}`（省略 = 该模型所有有样本的类别）。
- 响应 202 `{"job_id": "..."}`；已有训练任务 → 409；某类样本不足 → 400 `VALIDATION`，`detail.insufficient = {"B": 7}`。
- 训练完成：`metrics.json` 更新；若该模型为当前部署模型则自动触发 deploy（原始需求），WS 推送 `job` 与 `state`。

### GET /jobs/{job_id}
```json
{"job_id": "...", "type": "train", "model_id": 2, "status": "running", "progress": 0.42, "stage": "epoch 8/30 val_f1=0.93",
 "message": null, "started_at": "...", "finished_at": null, "result": null}
```
训练成功时 `result = {"metrics_summary": {...}, "artifacts": {"onnx": true, "engine": false}}`；失败时 `message` 为原因。

- `GET /jobs?active=true` 列表；`POST /jobs/{job_id}/cancel` → `{"cancelled": true}`。

## 11. WebSocket 事件流 /ws/events

连接后立即收到一条 `state` 全量事件，之后按需推送。消息格式 `{"type": "...", "ts": "...", "data": {...}}`：

| type | 触发 | data |
|---|---|---|
| `state` | 状态/故障/部署模型变化，及每 5 s 心跳 | 同 `GET /state` |
| `stats` | 每 1 s（running 时） | 同 `state.stats` |
| `job` | 任务创建/进度/完成/失败 | 同 `GET /jobs/{id}` |
| `capture_sample` | 采样切出一张小图 | `{"model_id": 1, "class": "A", "sample": {...样本项...}, "count": 57}` |
| `param_sync` | 参数下发下位机的最终结果 | `{"section": "valve", "mcu_ack": true, "error": null}` |
| `fault` | 故障产生/清除 | `{"code": "MCU_DISCONNECTED", "active": true, "detail": "..."}` |
| `mcu` | 下位机状态变化 | 同 `state.mcu` |

服务端每 5 s 发 ping，客户端需回 pong；断线后客户端重连并重新 `GET /state`。

## 12. 静态文件
- `/static/models/{id}/thumbs/{cls}/*.jpg`、`/static/models/{id}/samples/{cls}/*.png`（RGBA，alpha 为 mask；HMI 预览可直接显示）、`/static/snapshots/*.jpg`、`/static/previews/*.jpg`。只读；snapshots/previews 只保留最近 50 个。
