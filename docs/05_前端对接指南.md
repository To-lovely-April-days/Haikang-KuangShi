# 05 前端（HMI）对接指南

> **内部文档，不要直接发给前端。** 发给前端的只有两份：`docs/06_前端接口调用手册.md` 与 `docs/06_openapi_hmi.json`（由 `scripts/export_openapi.py` 从代码导出、去掉了后端备注）。本文供后端同事准备联调环境时参考。

给 HMI 前端同事的入门说明：接口契约本身在 `docs/03_前端接口清单.md`（权威）与 `docs/openapi.json`（机器可读），
本文只讲**怎么拿到接口、怎么把后端跑起来、联调时最容易踩的坑**。

仓库：https://github.com/To-lovely-April-days/Haikang-KuangShi （分支 `main`）

## 2. 基本约定（摘要，细节以 docs/03 §1 为准）

- 基地址 `http://<IP>:8000/api/v1`；WS `ws://<IP>:8000/api/v1/ws/...`；静态文件 `http://<IP>:8000/static/...`。
  响应里的 `image_url` 是站点相对路径（如 `/static/snapshots/xxx.jpg`），前端自己拼 origin。
- JSON UTF-8；时间 ISO 8601 带时区；枚举一律小写字符串；没有鉴权（局域网内部署）。
- 失败统一为 4xx/5xx + `{"error": {"code": "...", "message": "...", "detail": {...}}}`。
  常见 `code`：`VALIDATION`、`PARAM_OUT_OF_RANGE`、`NOT_FOUND`、`CONFLICT`（状态不允许，`detail.reasons` 给原因）、
  `DEVICE_OFFLINE`（相机/下位机离线，503）、`MCU_NACK`、`MCU_TIMEOUT`、`INTERNAL`。
- 所有写操作建议带 `request_id`（≤ 128 字符，放 JSON 顶层或 `X-Request-Id` 头）：60 s 内重复提交直接回放首次响应，不重复执行，
  回放响应带 `X-Idempotent-Replay: 1`。按钮重复点击、网络重试都靠它兜底。
- 后端是状态唯一来源：HMI 启动与 WS 重连后先 `GET /state` 全量同步，之后靠 `/ws/events` 增量更新，不要在前端自己推演状态。
- 长操作（训练、采样、部署、备份、喷阀检测）返回 `202 {"job_id"}`，进度与结果看 `GET /jobs/{id}` 或 WS `job` 事件。
- 原始需求里"操作按钮都要弹确认框"由 HMI 实现，后端不做二次确认。

## 3. 把后端跑起来（两种方式）

**方式 A：用后端同事在局域网里跑的 Mock 服务。** 地址以当天告知为准（形如 `http://192.168.x.x:8000`），
用 `config/hmi-dev.yaml` 启动，已放开跨源访问，前端开发服务器（如 `http://localhost:5173`）可以直接调用。

**方式 B：自己本机跑。** 需要 Python 3.10（Windows / macOS / Linux 均可），首次安装含 PyTorch，下载约 1~2 GB。

```bash
git clone https://github.com/To-lovely-April-days/Haikang-KuangShi.git
cd Haikang-KuangShi
python3.10 -m venv .venv
source .venv/bin/activate          # Windows PowerShell: .venv\Scripts\Activate.ps1
pip install -r requirements.txt
python -m oresorter.cli serve --config config/hmi-dev.yaml
```

- 验证：`curl http://localhost:8000/api/v1/health` 返回 `{"ok": true, "version": "..."}`；Swagger 在 `http://localhost:8000/api/v1/docs`。
- `config/hmi-dev.yaml` = Mock 相机（合成蓝底矿石图，按 9 kHz 行频节奏出块）+ Mock 下位机（所有指令立即 ACK）+ `cors_origins: ["*"]`。
  数据写在仓库目录下的 `./data`（删掉即重置）。换端口加 `--port 8001`。
- 生产（Jetson）上 HMI 与后端同源部署（直接访问算力盒 `IP:8000`，或由后端 `/static` 托管 HMI 静态文件），不开 CORS；
  若 HMI 最终独立部署，提前告诉后端把来源加进 `system.cors_origins`。

## 4. Mock 环境能验证什么、不能验证什么

- 能：全部 REST 接口与两条 WS；相机快照 / 预览有图（合成图）；参数读写；样本采集、训练、部署、任务进度；喷阀检测任务；状态机全部迁移。
- 相机：Mock 相机始终 `connected=true`，参数下发原样返回（真机会按步进对齐并返回实际值，`PUT /cameras/{id}/params` 的 `warnings` 会说明）。
- 下位机：Mock 立即 ACK，`param_sync` 事件总是 `mcu_ack=true`；真机可能出现 `MCU_NACK` / `MCU_TIMEOUT` 与 `fault` 事件。
- **运行前必须有已部署模型**：新数据目录上 `POST /run/start` 返回 409 `CONFLICT`，`detail.reasons=["NO_MODEL_DEPLOYED"]`。
  完整流程：`POST /models/{id}`（新建）→ `POST /models/{id}/classes/{cls}/capture`（采样，至少 2 个类别）→ `POST /models/{id}/train`
  （CPU 上通常几分钟）→ `POST /models/{id}/deploy` → `POST /run/start`。这条链本身就是图像页要做的功能，可以顺手联调。
- 不能：真机的采集耗时、相机离线（503 / `DEVICE_OFFLINE`）、下位机故障码、TensorRT 推理速度。这些留到算力盒联调。
- `POST /system/shutdown` / `reboot` 在开发配置下只记日志不真关机，响应与真机相同。

## 5. WebSocket 要点（最容易踩的坑）

**`/ws/events`（事件流）**

- 连上立刻收到一条 `state` 全量事件（与 `GET /state` 同结构）；之后 `state / stats / job / fault / mcu / param_sync / capture_sample` 按需推送。
- 服务端每 5 s 发文本 `{"type": "ping"}`，客户端**必须回文本** `{"type": "pong"}`；连续 15 s 没收到任何客户端消息以 1001 断开。
  浏览器的 WebSocket 对象不暴露协议层 pong，所以一定要在应用层回。
- 断线重连后首条 `state` 就是全量，可代替一次 `GET /state`。

```js
const ws = new WebSocket(`ws://${host}/api/v1/ws/events`);
ws.onmessage = (ev) => {
  const msg = JSON.parse(ev.data);
  if (msg.type === "ping") { ws.send(JSON.stringify({ type: "pong" })); return; }
  if (msg.type === "state") store.replaceState(msg.data);       // 全量
  else if (msg.type === "job") store.upsertJob(msg.data);        // 同 GET /jobs/{id}
  else if (msg.type === "fault") store.setFault(msg.data);       // {code, active, detail}
  // stats / mcu / param_sync / capture_sample 见 docs/03 §11
};
ws.onclose = () => setTimeout(connect, 1000);
```

**`/ws/preview/{id}`（连续预览）**

- 每帧两条消息：先文本 `{"type": "frame", "seq", "w", "h", "start_px", "end_px", "ts"}`，紧接一条二进制 JPEG。
- 查询参数越界不夹断：先收 `{"type": "error", "code": "PARAM_OUT_OF_RANGE", ...}` 再被 1008 关闭；相机离线收 `DEVICE_OFFLINE` 后 1011 关闭。
- `fps` 上限是 `GET /system/info` 的 `preview_max_fps`（默认 10）；`mode=edges` 输出宽度恒为 `2 × edge_px`。
- 预览通道不需要回 pong；关闭连接即停止。

```js
const ws = new WebSocket(`ws://${host}/api/v1/ws/preview/1?mode=full&fps=5&max_width=1000`);
ws.binaryType = "blob";
let meta = null;
ws.onmessage = (ev) => {
  if (typeof ev.data === "string") {
    const msg = JSON.parse(ev.data);
    if (msg.type === "error") { showError(msg); return; }   // 服务端随后会关闭连接
    meta = msg;                                             // 下一条二进制就是这帧的 JPEG
    return;
  }
  const url = URL.createObjectURL(ev.data);
  img.onload = () => URL.revokeObjectURL(url);
  img.src = url;
};
```

## 6. 联调顺序建议

docs/03 §2 有"界面 → 接口"逐控件对照表。建议顺序：

1. `GET /health`、`GET /state`、`/ws/events`（含 ping/pong 与重连）。
2. 运行控制页：`GET /params`、`PUT /params/valve|clean|outputs`、喷阀检测四个接口（任务 + `job` 事件）。
3. 功能页（相机）：`GET /cameras`、`GET/PUT /cameras/{id}/params`、`POST /cameras/{id}/snapshot`、`/ws/preview/{id}?mode=edges`、`awb-once`。
4. 图像页：模型增删改、样本采集 / 列表 / 删除 / 撤销 / 清空、采集设置与 `POST /capture/preview`、训练与 `GET /jobs/{id}`。
5. 开始页：`GET /models/current`、部署、运行 / 暂停 / 停止、`GET /run/stats` 与 `stats` 事件。
6. 顶栏 / 底栏 / 高级设置：`POST /system/save`、`system/info`、`PUT /params/feed`。
